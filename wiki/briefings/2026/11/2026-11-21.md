# AI Frontier — November 21, 2026

**Frontier signal:** Agent infrastructure is increasingly making transient context, tool output, shared work state and domain actions explicit artifacts. But persistence, compression and approval UI are different mechanisms; none by itself establishes correct external outcomes. Four selections concern coding/runtime operations (80%) and one explores model-based engineering (20%). The sources are maintainer documentation and an alpha release, not independent benchmark replication. Dates below distinguish release from observed repository activity.

## 1. OpenAI Agents SDK 0.24.0-alpha.7 — durable root sessions

**Source date:** November 8, 2026 (older alpha pre-release). **Primary URL:** https://github.com/openai/openai-agents-python/releases/tag/v0.24.0-alpha.7. **Canonical entity:** [[projects/openai-agents-sdk]]. **Verdict:** Worth prototyping for recovery semantics; not a stability guarantee.

**Demonstrated capability:** The release documents durable root Sessions through caller-owned CustomStorage, native and classic execution side by side, and strict default environment write policies. The SDK README documents sandbox agents for file inspection, commands and patches.

**General concept:** Persistence of agent state is distinct from verified external effects. **Specific mechanism:** Storage-backed session reconstruction and explicit executor write-policy configuration. [[concepts/agent-state-and-lifecycle]] and [[concepts/replay-idempotency-and-effect-semantics]] explain why uncertain writes require reconciliation.

**Novelty and limits:** An incremental but consequential alpha migration. The vendor specifically cautions about executor policy changes and uncertain tool effects; no measured crash-recovery success or independent safety assessment is cited.

**Practical implication:** Prototype storage-backed coding agents against disposable repositories, and test write boundaries before adopting alpha defaults.

**Bounded experiment:** Run 20 mocked edit-and-remote-write tasks, inject crashes on both sides of a remote commit, resume from storage, and measure duplicate effects, unresolved writes and unauthorized filesystem changes. No test executed here.

## 2. Planning with Files — explicit plans across context loss

**Source date:** Repository activity observed November 20, 2026; original publication date unverified. **Primary URL:** https://github.com/OthmanAdi/planning-with-files. **Canonical entity:** [[projects/planning-with-files]]. **Verdict:** Practical low-infrastructure experiment.

**Demonstrated capability:** The repository describes Markdown-backed plans, findings and progress that can be recovered after conversation clearing or compaction, plus re-injection hooks and a deterministic completion gate.

**General concept:** Persistent task memory and recovery of planning context. **Specific mechanism:** External Markdown artifacts plus recurring context reintroduction, rather than assuming a long chat transcript remains available. [[techniques/agent-skills-and-memory]] and [[concepts/verified-completion-vs-apparent-success]] explain the limits.

**Novelty and limits:** An accessible, agent-agnostic implementation of established file-state planning; compatibility claims are maintainer-reported. A recovered plan can be stale, and a completion gate cannot verify requirements it does not encode.

**Practical implication:** Try it on a long-running repository maintenance job where context compaction otherwise loses task status.

**Bounded experiment:** Interrupt 20 fixed coding tasks mid-run, compare no plan, persisted plan, and persisted plan with re-injection, and score hidden acceptance, stale-plan mistakes, tokens and recovery time.

## 3. sqz — deterministic compression before tool output enters context

**Source date:** Repository activity observed November 12, 2026; this is an older discovery, not a dated new release. **Primary URL:** https://github.com/ojuschugh1/sqz. **Canonical entity:** [[projects/sqz-context-compression]]. **Verdict:** Worth a controlled trial on noisy CI output.

**Demonstrated capability:** The Rust tool formats command output and substitutes references for previously seen content; source code, stack traces and certain sensitive lines are treated conservatively. The README reports 3,003 compressions, 178,442 tokens saved and a 24.7% average reduction in one developer's use.

**General concept:** Delivered-context information and management cost differ from raw token count. **Specific mechanism:** Command-aware deterministic formatting plus reference-based deduplication and expansion. [[concepts/information-content-dominance]] cautions that reducing tokens does not prove retained diagnostic usefulness.

**Novelty and limits:** Unlike model-based summarization, the described compressor requires no LLM. The figures are maintainer telemetry, not independently verified task-quality gains; savings depend heavily on repeated or verbose outputs.

**Practical implication:** Benchmark compression against your own build/test logs before integrating it into an autonomous repair loop.

**Bounded experiment:** Replay 30 recorded tool traces with raw, formatter-only and formatter-plus-dedup output. Score diagnostic fact retention, repair acceptance, context tokens and expansion failures. Keep the model and prompts fixed.

## 4. OpenAgents Workspace — shared human-agent coordination

**Source date:** November 20, 2026 repository activity; v1.1 release date not independently established. **Primary URL:** https://github.com/openagents-org/openagents. **Canonical entity:** [[projects/openagents-workspace]]. **Verdict:** Useful architecture reference for multi-agent workspaces.

**Demonstrated capability:** The README describes cross-runtime shared threads, files and browsers, private-by-default agent sharing, role-based routing, issues, and approval cards for deployment, spending and destructive actions. Repository workflow history shows a November 20 change titled 'save an agent message as knowledge'; its diff was not verified.

**General concept:** Shared work context does not imply shared authority or trustworthy evidence. **Specific mechanism:** Persistent workspace with separately described ownership, routing and approval surfaces. [[concepts/delegated-authority-and-revocation]] and [[techniques/multi-agent-orchestration]] frame the boundary.

**Novelty and limits:** An implementation-level coordination platform rather than a new agent algorithm. Maintainer documentation is not a penetration test or proof of cross-user isolation.

**Practical implication:** Separate workspace membership, agent-use permissions and irreversible-action approval in agent team designs.

**Bounded experiment:** Connect two test agents and one reviewer; attempt ten simulated publish/delete actions under private and shared threads, including denial and restart. Measure unauthorized effects, artifact visibility and approval enforcement.

## 5. Simulink Agentic Toolkit — structured model-based engineering

**Source date:** Repository activity observed November 21, 2026; initial release date unverified. **Primary URL:** https://github.com/matlab/simulink-agentic-toolkit. **Canonical entity:** [[projects/simulink-agentic-toolkit]]. **Verdict:** Exploratory but particularly relevant to engineering workflows.

**Demonstrated capability:** MathWorks documents MCP tools for Simulink model overview, reading, editing, checking and diagnostics, paired with model-based-design skills. The toolkit requires MATLAB R2023a or later with Simulink; some tests and specialized skills need additional products.

**General concept:** Domain skills plus structured tool contracts can make engineering artifacts manipulable by agents without implying certified outcomes. **Specific mechanism:** An MCP server exposes typed model operations while skills encode domain procedures. [[concepts/contracts-and-compositional-correctness]] distinguishes local structural checks from whole-system acceptance.

**Novelty and limits:** A domain-specific bridge from coding agents into model-based engineering. The README documents capabilities but no independent benchmark showing requirements correctness or functional safety; simulation and structural checks cannot substitute for physical validation.

**Practical implication:** Use disposable example models to evaluate agent-assisted model review, not production safety-critical control designs.

**Bounded experiment:** Plant connection and parameter defects in five example models; compare tool-only versus tool-plus-skill agents, measuring detected defects, valid model changes, simulation outputs and independent reviewer acceptance.

## Cross-item interpretation

These projects occupy different layers of one engineering stack: [[projects/openai-agents-sdk]] persists execution context, [[projects/planning-with-files]] persists task intent, [[projects/sqz-context-compression]] transforms observed tool output, [[projects/openagents-workspace]] coordinates people and agents, and [[projects/simulink-agentic-toolkit]] exposes a domain-specific effect surface. They have not been demonstrated as one integrated system. The meaningful test is whether state restoration, compressed evidence and approval gates preserve **independently accepted task outcomes**, not whether the interfaces appear convenient. See [[concepts/verified-completion-vs-apparent-success]], [[techniques/durable-agent-execution]] and [[techniques/evaluation-and-simulation]].

A practical next experiment is a 20-task coding workflow with a persisted plan, crash-recoverable session, optional output compression and an independent final checker. Factorially vary each layer, report previously solved cases lost and unknown remote effects, and never infer reliability from a single successful demonstration. No experiments in this briefing were run.
