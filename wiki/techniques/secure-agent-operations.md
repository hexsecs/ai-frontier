# Secure agent operations

## What it is

Secure agent operations is the set of mechanisms by which the systems in this corpus let an agent act in the world — call tools, write to repositories, close security alerts, handle credentials — while keeping those actions governable: gated before they execute, confined to channels an operator can enumerate, recorded in a form that supports an account, and tested against an adversary rather than assumed safe. The corpus's contributions divide by role. Two projects are governance systems: [[projects/openbot]], a policy gateway in front of a self-hosted agent coworker, and [[projects/github-contribution-check]], a scheduled reviewer whose every write travels a validated channel. One is a detection operation, [[projects/aisoc-v21]], which gates its most consequential act — closing an alert — on the provenance of the measurement behind it. One supplies the adversarial test the others lack: [[projects/angler]] measures how web agents fare against an attacker that learns. And two studies document the channels through which operations fail: [[projects/security-impact-of-coding-agent-memory-files]], on auto-loaded instruction files as an injection surface, and [[projects/pre-crime-for-agents]], on a monitoring tripwire whose limits are as instructive as its accuracy.

Two cross-cutting claims organise the material. First, where these systems are trustworthy, the trust is structural — a property of tokens, schemas, ordering, and call paths — rather than instructional: that is [[concepts/structural-constraint-over-instruction]], and every mechanism below is an instance of it. Second, each mechanism's assurance extends only as far as the scope it actually exercises — [[concepts/scoped-assurance]] — and the corpus is unusually good at stating those scopes, including the cases where the exercised scope turns out to be empty.

## Mechanism variants

**Policy gateway with audit-before-act — [[projects/openbot]].** Every action a Bot takes to a computer, file, MCP server, or component returns to a single server-side gateway, which resolves the target, evaluates the current policy, *writes the audit row, and only then calls the computer* — "there is no path that acts without the record existing first." Policy is CEL over an enumerated field catalog (below), evaluation is deny-before-allow, and the engine fails closed: a missing or empty policy permits nothing, a broken deny rule denies. Isolation is per person — each person's Bots get their own container, browser profile, and workspace — and egress passes through a filter proxy that permits nothing until a policy has been pushed. The designed fallback is human takeover: a Bot that meets a login wall, a 2FA prompt, or a CAPTCHA files an audited help request, and while a person drives, Bot actions are refused rather than queued. OpenBot never solves a bot check on anyone's behalf.

**Structural write channels — [[projects/github-contribution-check]].** Contribution Check puts a language model inside a repository's write path by removing every other way to write. Deterministic shell pre-steps decide what gets reviewed and assemble schema-validated evidence files before any model runs. The orchestrator's token is read-only throughout; the specialist checker it dispatches is fenced — pre-fetched evidence only, labelled "untrusted data, not instructions," forbidden from fetching, and required to return a structured abstention (❓ / `triage:error`) rather than improvise when evidence is missing. No agent holds write credentials: every write is a *safe output*, a structured request that a separate job validates and applies, configured as a closed set — one report issue, at most ten comments, exactly four quality labels. Cost is bounded the same structural way: a 3-PR-per-run cap, a 30-minute timeout, a 50-turn limit, a daily AI-credit ceiling.

**Provenance-gated detection operations — [[projects/aisoc-v21]].** AiSOC runs LLM agents over security telemetry, but its operational discipline is about what a measurement is allowed to *do*. Investigations are written to an auditable ledger; copilot answers carry citations, and claims that cannot be cited are labelled *uncited* rather than dropped. Version 21 made serving-model provenance a gate on action: a score carries a five-state `provenance_status`, a run whose serving identity mismatches the requested model is refused as that model's performance, and — the operational form — a clearing measurement over an unattributed call now **blocks** auto-closure instead of authorizing it. Response itself is governed: playbooks preview before acting behind three opt-in switches, approval is a durable pause that survives restart, the approver must hold the required tier and must not be the requester, and retro-hunts can run in a dry-run mode that withholds every mutation at the write boundary while consuming the sweep exactly as live.

**Runtime tripwires — [[projects/pre-crime-for-agents]].** Pre-Crime tests the monitoring end of operations: a linear probe on a pressured agent's activations scores each call *before it generates anything*, aiming to flag the call about to leak a protected value. As a mechanism it is genuinely pre-emptive in timing — the score exists before the reply or tool call — and its measured per-call accuracy is high (Evidence, below). Its bounds are equally part of the mechanism's description: it detects a coming *disclosure*, not a rule violation, and as forecasting it is near chance. It belongs in an operations toolkit as a last-second tripwire feeding a halt-or-review decision, not as a compliance gate.

**Adversarial testing as an operations input — [[projects/angler]].** ANGLER is not a defence; it is the test an operator should expect a defence to face. Inside the REEF benchmark — nine executable website clones with state-based verifiers — an adaptive attacker mutates injections with an LLM and selects among them with a contextual bandit fed by verifier outcomes across rollouts. The operational lesson is twofold: fixed attack suites underestimate vulnerability, because adaptivity against the *same* validated candidate pool finds substantially more successes; and engagement is not success — click-through on a lure and final-state compromise diverge sharply, so an operations metric that stops at "did the agent follow the injection" misreads both directions.

**Two named patterns cut across the variants.** The first is **gated admission at runtime boundaries**: free-form model output becomes consequential only after passing a deterministic gate it does not control. Contribution Check's safe outputs and OpenBot's policy gate are the operations instances of a pattern the mining register records across the corpus — schema-validated objects before code consumes them, components admitted to libraries only after frozen tests. In operations the gate sits on actions and writes rather than artifacts, but the shape is identical, and so is the register's residue: a system's effective trust boundary is exactly its gate's schema. The second pattern is **trust-boundary-as-catalog**: the policy surface is not described in prose but *enumerated as a field catalog*, and the governable world is exactly the catalog. OpenBot's CEL fields — `tool.name`, `intent`, `page.url` / `page.host`, `element.ref`, `command`, `file.path`, `mcp.server` / `mcp.tool` / `mcp.effect`, and the distinctive `initiator.kind` / `initiator.id`, carried inside a signed run assertion so a Bot cannot relabel its own run — are the fullest instance; Contribution Check's closed safe-output set is the write-side form. The pattern's power and its limit are the same fact: anything outside the catalog — a raw socket that bypasses the egress proxy, the internal loop of a Bot served from its own endpoint — is outside governance by construction.

## Evidence and measured effects

The honest summary is that this corpus contains exactly one project that measures its own security-relevant behaviour at any scale, one that measures the attack side, and two governance systems whose evidence is design inspection plus, in one case, vendor telemetry. All figures below are author-reported; none is independently replicated.

**AiSOC's verdict eval** (author-run, published methodology) grades models on a 72-item hand-authored synthetic corpus through the production triage path. The best balanced accuracy is 0.357 against a 0.250 constant-answer floor; auto-close precision ranges from 0.091 to 0.571 across the five measured small local models. The scorecard's own conclusion is the operations finding: "nothing measured here supports autonomous closure." Alert reduction is published as three labelled figures for three methods — 33.3% is the production correlation method on a noisy 1,000-alert stream; the 75.3% legacy figure is one the project itself says "does not describe this product." No hosted or frontier model has ever been measured in the system.

**ANGLER's attack measurements** (single preprint, author-reported) put average attack success at 20.36% for the adaptive attacker against 15.24% for a non-adaptive baseline selecting uniformly at random from the same compiler-validated candidate pool — the contrast isolates adaptivity, not superiority over other adaptive attackers, none of which was run head-to-head. Benign task success falls from 61.9% attack-free to 44.4% under ANGLER, so injection damages the user's work even when the malicious objective fails. Direct prompt injection is the strongest type (31.5% average success; 56.6% against GPT-4o, the highest single cell), and the two backbones that almost never engage injected page content are still compromised by direct injection at field-comparable rates.

**Pre-Crime's tripwire numbers** (single-author preprint, author-reported): per-call AUROC 0.98 on held-out Qwen3-32B episodes, catching 82% of leaking calls at a threshold flagging 5.5% of calls in refusing episodes. The bounds travel with the numbers: episode-level forecasting scores 0.53–0.61, near chance; a trained TF-IDF text classifier on the same labelled calls reaches 0.96, so the activation-specific edge is small; and thresholds calibrated on one episode set flag 29% of refusing episodes in another, against roughly one in twenty expected — the [[concepts/scoped-assurance]] failure in its calibration form.

**The memory-file study** (single paper, author-reported, preliminary) is the corpus's one measurement of an operations *channel*: planted project memory files moved the share of secure completions by −8 to +6 percentage points across three agent configurations, every shift inside the band the authors say cannot be told from chance. The sharp result is about disclosure, not code: of 18 sessions whose reasoning explicitly called the file an attack, only 4 named it in the final message, and recognition did not protect the code — those sessions still lost security against baseline in 3 cases and gained it in 2.

**The governance systems measure almost nothing.** Contribution Check's entire published evidence is one vendor telemetry paragraph: three runs in GitHub's own repository, each ~8–9 minutes, ~30,000 tokens, zero errors — with no accuracy evaluation of the checker's verdicts against human judgment, and built-in eval questions that test only that dispatch and reporting happened. OpenBot publishes no measurements at all: no benchmarks, no task-success or refusal-quality figures, no adversarial evaluation of the gateway. Its support is an auditable mechanism described in its own documentation, which is a real but different kind of evidence.

## Failure modes and bounds

**The shipped allow-all default.** OpenBot's gateway is structurally fail-closed and substantively empty as shipped: the startup policy is `deny: []` / `allow: ["true"]`, so a fresh deployment permits everything until an operator writes real policy. The engine's guarantees describe what the mechanism *can* enforce; in a default deployment the audit trail records permitted actions, not enforced refusals. This is [[concepts/structural-constraint-over-instruction]]'s sharpest bound, and it attaches to the catalog pattern too: a catalog can enumerate, in perfect detail, a boundary that is currently set to admit everything.

**Memory as an uninspectable control surface.** Project memory files are loaded automatically, treated as trusted project guidance, and — per the documentation the study cites — are *context, not enforced configuration*: nothing in the channel lets an operator enumerate what the file will make the agent do, and the study shows the influence is rarely surfaced where a user reads (4 of 18 attack-flagging sessions disclosed it in the final message). Screening by keyword cannot work: the planted files avoid security vocabulary entirely and read as ordinary engineering conventions. The operational consequence the authors draw is procedural, not technical — review memory-file diffs as security-relevant diffs, and run security tests on agent-produced patches, because a clean final message proves nothing.

**Self-referential assurance.** Two instances, one per direction. AiSOC's pre-v21 scorecards published verdict numbers for calls whose serving model no party could name — `resolved_models: []` on every row — so the detection platform's own assurance rested on unattributed measurements until the project disclosed and repaired it; its substrate harness is, by its own methodology document, "tautological by construction," passing as long as the substrate stays internally consistent. Pre-Crime's probe shows the milder form recorded under [[concepts/evaluator-circularity]]'s logic: the dramatic comparison (82% vs 26% of leaking calls caught) is against an *untrained* monitor, while the trained text baseline nearly matches the probe — a shield whose measured edge depends heavily on which comparator its constructor chose. And because the probe reads disclosure rather than violation, an operator who halts on its alarms mostly halts legitimate sharing: at the demonstrated operating point, 59% of never-leaking episodes see at least one flag.

**Catalog edges are governance edges.** OpenBot's own documentation lists its non-controls: a `knowledge.yaml` that is "validated, but nothing reads it yet"; a group declaration no sign-in path populates; an egress proxy that raw sockets bypass, with that layer explicitly assigned elsewhere; and token-protected lower-level endpoints beside the gateway that operators are warned not to use as a bypass. A Bot's internal loop at its own AG-UI endpoint never routes through the gateway at all. Enumerating the boundary makes these edges *findable* — OpenBot's candour is the corpus's best — but does not close them.

**Constraints cap capability as well as misuse.** Contribution Check's fence is also its ceiling: the 3-PR cap silently skips pull requests in a busy repository (the report discloses the skipped count; skipped PRs are never revisited), and the rubric is truncated to the first 1,500 plus last 500 characters of the guidelines, so rules in the middle are "unenforced and unenforceable by this design." A perfectly fenced reviewer can also simply be a wrong reviewer — nothing published measures whether its verdicts agree with maintainers.

**No defence in this corpus has faced the adaptive attacker.** ANGLER evaluates no mitigation; OpenBot and Contribution Check evaluate no attacker. The claim "this gateway would blunt an adaptive injection campaign" is therefore unsupported in both directions — plausible, untested. What the corpus does support is the weaker operational stance: assume fixed test suites flatter the defence, and measure final-state outcomes, not engagement.

## Open questions

- Would any mechanism here measurably reduce success for an ANGLER-class adaptive attacker? No page in the corpus runs that experiment, and it is the obvious next measurement for both governance systems.
- How often do real OpenBot deployments replace the allow-all default, and with what? The mechanism's real-world assurance is exactly this unmeasured operator behaviour.
- Does provenance-gating generalise beyond AiSOC's closure decision — should any agent action above a consequence threshold require a measurement whose producer is attested, and what does that cost in refused legitimate work?
- The memory-file study is preliminary and its authors plan a prevalence study: how common is the planted shape — guidance that discourages defensive checks — in real repositories' memory files, malicious or merely sloppy?
- Can a tripwire threshold be calibrated to transfer across episodes and models, or is local calibration on held-out traffic a permanent operating cost of probe-based monitoring?

## Evidence status

The governing fact about this page's subject is that **the corpus's security mechanisms are mostly design-verified, not effectiveness-measured** — the register candidate named *auditability-is-not-effectiveness*: a mechanism can be maximally inspectable, its guarantees checkable line by line in public sources, while whether it catches real misuse, and at what cost in refused legitimate work, remains entirely unmeasured. OpenBot is the pure case (a complete audit-first design, zero published measurements); Contribution Check is close behind (a fully checkable workflow source, three runs of vendor telemetry, no verdict-accuracy evaluation). The exceptions prove the rule by their limits: AiSOC measures, but its numbers are author-reported, its corpora synthetic and hand-authored, its models small local ones, and there is no independent replication; ANGLER and Pre-Crime are single preprints, author-reported and unreplicated, and ANGLER releases no code or data. Vendor claims, author-reported results, and design inspection are labelled as such throughout this page, and no claim here rests on a benchmark this KB reproduced.

One candidate link was tested and demoted in preparing this page: [[projects/vericua]]. VeriCUA's subject is post-hoc *verification* — whether a completed task was actually done, judged after execution by a read-only verifier — and it belongs to [[techniques/verification-and-evidence]]. Its read-only-by-construction inspection (allowlisted getters, before/after digests) is a design operations can borrow, but borrowing a property does not make a verification procedure an operations mechanism, and its evidence (verdict accuracy against gold labels) answers a verification question, not an operational one. The remaining six candidate links were checked against the deepened project pages and kept.

## November 12 synthesis: planning boundaries versus measured harness security

[[projects/baya-compile-then-execute]] (https://arxiv.org/abs/2611.06039) compiles web operations before untrusted page observation; its authors report 0% WASP attack success and 77.8% WebArena utility in their test conditions. [[projects/fastbrowse]] (https://github.com/agent-labs-dev/fastbrowse) instead chooses from actual page controls and gates sensitive actions in code. These are **different mechanisms**, not a measured head-to-head. [[projects/harness-matters-web-agent-security]] (https://arxiv.org/abs/2611.11971) supplies an important counterweight: harness security varies with stage and model, and apparent defenses require paired benign-task calibration. No independent replication of Baya or fastbrowse is recorded, and neither result establishes safety against all prompt injection.

**Proposed reproducible test:** ten paired benign/adversarial controlled sites; fixed model and budgets; compare compiled task API versus constrained reactive controls; measure legitimate utility, unauthorized side effects, false-success and stage-specific failure. Preserve existing security-gateway counterexamples; do not infer that prompt-level refusal alone enforces access policy.
