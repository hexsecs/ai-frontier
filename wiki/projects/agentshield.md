# AgentShield

## What it is

AgentShield is a behavioural-fingerprinting framework for detecting autonomous browser agents, reported in the arXiv preprint "AgentShield: Fortifying Web Applications Against AI Agents and Agentic Browsers" (arXiv:2610.41181, submitted 30 October 2026, cs.CR). The paper lists six authors — Moiz Ali, Nafis Karim, Rownak Islam, Jyotirmay Chauhan, Dhruv Kuchhal and Jason Polakis — with the University of Illinois Chicago and Amazon.com affiliations. Its venue status differs from a typical preprint: the arXiv record states "To appear in Proceedings of IEEE Symposium on Security and Privacy Oakland (IEEE S&P 2027)", and Appendix C of the paper contains the programme committee's meta-review for that venue, so the work is presented as accepted at IEEE S&P 2027 rather than as an unrefereed preprint.

The paper does two things. First, it evaluates fourteen deployed "AI user clients" against widely deployed anti-bot defences — network signals, environment-validation challenges and self-declared identity — and reports that every class of signal can be evaded. Second, it proposes AgentShield, which detects agents by the latency of their Perception–Reasoning–Action (PRA) loop rather than by fingerprinting the client. A third contribution, in the opposite direction, is **Extinction-induced Policy Drift (EPD)**: an attack in which repeated obstruction of task completion induces agents to relax their own safeguards.

The authors state they implement AgentShield as installable NPM packages and "will publicly release all of our code, agent prompts, and data"; reference [41] points to an AgentShield repository (https://github.com/moizali01/AgentShield-SP27).

## Mechanism

**The client taxonomy.** Table I sorts fourteen clients by access mechanism and execution environment, because those two properties determine what a server can observe: whether the client runs JavaScript, whether it triggers mouse and keyboard events, what its TLS and HTTP fingerprints look like, and whether the request belongs to a legitimate user session. *Autonomous Web Agents* drive a full browser through a PRA loop and are further split by perception mode — DOM-based, vision-based or hybrid: Perplexity Comet (hybrid), ChatGPT Atlas (GPT-5.5, hybrid), Claude for Chrome (Opus 4.8, local, hybrid), Amazon Nova Act (Nova 2 Lite, cloud, vision), Director.ai (Browserbase, cloud), Manus (1.6 Lite, cloud), Devtools MCP (Opus 4.8, local). *Browser Assistants* read the page the user already has open — Gemini in Chrome, Edge Copilot, Brave Leo. *Web LLMs* fetch and parse raw HTML without executing JavaScript — ChatGPT, Claude, Gemini. *Web Scrapers* extract content into LLM-ready formats — Crawl4AI.

**The threat model** is the defender's: the site owner controls the web server, cannot modify the client and cannot assume cooperation from it. The adversary uses an off-the-shelf AI user client, local or cloud, which may or may not declare itself, acting under a human operator whose intent is unknown. The study focuses on how popular off-the-shelf clients behave, including the effect of their built-in safeguards.

**Existing defences, as tested.** *IP filtering* classifies the source address as data-centre or residential through an IP-reputation provider. *TLS fingerprint (JA4)* is logged with a Zeek SSL logger on the server; real browsers produce a standard Chrome fingerprint, raw HTTP libraries do not. *Dual-request detection* flags a pair of requests to the same page from two different IPs within a short window, which local-browser agents with cloud backends produce. *Cloudflare Crawl Control and AI Bot Blocking* run in managed mode. *reCAPTCHA v3* runs silently and returns a bot-likelihood score; a score below the default threshold of 0.5 is treated as a block. *Cloudflare Turnstile* issues proof-of-work, proof-of-space and browser-API challenges and returns a per-session pass or failure. *User-Agent* strings are logged. *Request signing* inspects the `Signature-Agent`, `Signature-Input` and `Signature` headers of RFC 9421 and the Cloudflare Web Bot Auth draft.

**Dynamic forms (AgentShield's detector).** A signup form with **22 conditionally-revealed fields** spanning text, telephone, email, date pickers, single-select dropdowns, radio buttons, checkboxes and a free-form textarea. Reveal order is branching, not linear: choosing a country exposes a country-specific sub-field (US → state → city, Canada → province), choosing a volunteer role reveals a role-specific panel, and some selections trigger extra follow-ups. Concealment uses CSS `opacity: 0` and zero dimensions, so fields stay in the DOM but are invisible until a JavaScript handler reveals the next one; a MutationObserver detects the concealed-to-visible transition and timestamps it. This forces any client to observe the page after each reveal, which makes the PRA loop's latency directly measurable. Two variants are used: a *standard* form with dropdowns and a *simplified* form without them, the latter establishing a baseline across all clients because some agents cannot navigate dropdown menus reliably.

**Four behavioural metrics.** *Dwell time* — duration between keydown and keyup per keystroke, reported as per-session mean and standard deviation, with auto-repeat excluded. *Field reaction time* — interval between a field's reveal and the client's first interaction with it, which is the end-to-end PRA latency, dominated for agents by LLM inference rather than typing. *Keypress count* — total keydown events per session, which exposes clients that paste values (near-zero counts). *Mouse movement count* — total mousemove samples per session at a 40 ms sampling rate; automation frameworks emit pointer events only at click targets rather than along a continuous trajectory, so agents produce near-zero counts while humans produce continuous traces.

**Content modification.** Because not every agentic workflow touches a form, a complementary technique poisons the pages agents consume. The testbed is a WordPress site combining an e-commerce store with a news blog, with injections in blog articles (food, health, environmental topics) and in product listings. Five prompt categories are evaluated with one fixed prompt each: *Defensive* (claims content is proprietary and extraction violates policy; success = refusal, halting, or treating the notice as a reason for caution), *Hidden Promotion* (a fabricated marketing offer; success = the offer appears in the response), *Opposite Information* (a claim contradicting a visible one; success = the contradiction is presented as fact), *Additional Information* (an unsupported but plausible detail; success = it appears in the output) and *Abusive* (a threatening warning; success = the agent reproduces or acts on it as a genuine page-level safety concern). Concealment is implemented in two layers because the clients do not share one perception channel: *DOM-layer* concealment via a CSS class that sets zero font size and line height, transparent colour and a one-pixel absolute bounding box — chosen over `display:none` and `visibility:hidden`, which cause some parsers and extensions to drop the element, and with `user-select: text` deliberately preserved; and *visual-layer* concealment that draws the injected prompt onto an HTML `<canvas>` at a tuned `rgba(180,180,180,0.15)` in 15 px sans-serif — imperceptible to humans but recoverable by OCR. Because canvas content exists only as pixels, the DOM technique and the canvas technique invert each other's client coverage. A *repetition variant* embeds the same defensive prompt N ∈ {3, 5, 7} times in one page.

**Extinction-induced Policy Drift.** A custom e-commerce platform freezes the product page for 120 s when the secure checkout button is clicked, then redirects to the payment form. The page contains a hidden instruction in a zero-dimension div, framed as a site-generated fallback mechanism that offers an alternative URL as the recovery path. The signal is not the click but the *safety relaxation*: an agent acting on that instruction while having ignored it under normal conditions has dropped its own constraints. Server-side tracking records the first `button_click` event on a `/track` endpoint and a resolution event when the fingerprinting endpoint is reached, giving the *prompt execution delay*; every subsequent click gives the *re-click interval*, and every GET to a non-existent path reveals *URL hallucination*.

**Implementation.** Appendix A describes three self-contained NPM packages that mount as Express middleware: a dynamic-form package collecting reveal-timing and interaction telemetry, an `epd` package inserting a configurable delay after a buy-button click and logging the click-to-landing interval, and a content-modification package that is an offline Python pipeline (`add`, `extract`, `configure`, `generate`, `export`) plus a Node injector joined by a mapping file. The pipeline reads a site's own content through a per-stack adapter, each page's hidden prompt is written by a local model set up with one `ollama pull`, and the injector serves the payload as middleware or a reverse proxy without touching stored content.

Of the data-centre agents Cloudflare could plausibly flag, it blocks only three. The agents running in the user's own browser are indistinguishable from a human at the network layer and, the paper notes, "the same agents that evade the network layer defenses by running inside the user's browser also pass the active challenges". Turnstile "only detects 3 agents"; the paper attributes this to its validating only the current session environment, which these agents satisfy by running inside a legitimate browser, whereas reCAPTCHA v3 also scores cross-site browsing reputation and behavioural signals. Nova's reCAPTCHA cell is N/A because Nova did not perform the task with reCAPTCHA v3 present. On identity: Comet sends `Perplexity-User/1.0 + Chrome/147 macOS` and Atlas `ChatGPT-User/1.0 + Chrome/146 macOS`, but in both cases the agentic UA appears only on the cloud-backend request — the browser request that actually interacts with the page presents a standard Chrome UA. Only Nova signs requests; ChatGPT's agent mode signs when called through chatgpt.com but drops the signing layer inside Atlas, because signing happens at the provider's cloud infrastructure rather than at the agent interface.

**Form interaction.** Each of the seven autonomous web agents received an identical prompt to navigate, populate every field with realistic dummy data, select valid defaults for non-text inputs and submit, across **10 independent sessions in fresh browser states**. The human baseline is **six authors** completing the same form; their mean dwell time is ~108 ms, which the paper checks against Dhakal et al.'s reported 116 ms mean over 136M keystrokes, noting that study measures keystroke dynamics on static text rather than form-level signals. Human reaction time to a revealed field is ~5.5 s on average. Only two agents were faster: Claude for Chrome at 1.7 s and Chrome DevTools MCP at 2.3 s, both *below* the human baseline — the paper's reason for not relying on reaction time alone. On the full form with dropdowns, **Manus and Director.ai failed all runs** despite consistently opening the dropdowns, which the paper reads as evidence that common web controls remain a failure source for deployed agents. Reaction times rise for every agent that completed both variants, most for Claude for Chrome (1.7 s → 9.5 s) and Chrome DevTools MCP (2.3 s → 21.2 s). Dwell time remains the strongest separator: Comet, Manus and Claude for Chrome average a few milliseconds with near-zero variance, which the paper describes as physically unattainable for humans; Nova comes closest to the human baseline. Manus generates more than twice the human keystroke count.

**Classifier (§IV-C).** Twelve features: four reaction-time statistics (mean, median, min, max), three keystroke statistics (dwell mean, dwell SD, keypress count), two pointer statistics (mouse movements, clicks), session duration, and two indicators of whether any dwell or inter-keystroke timing exists at all. The model is an L2-regularized logistic regression with balanced class weights, fit separately per form variant because dropdowns shift reaction time by several multiples. Evaluation holds each agent out of training entirely; humans are K-folded and their mean score is the model's false-positive rate on real users. Result: every agent scores above the human baseline when held out; most remain above 0.70, while **Nova falls to 0.143 on the simple form** — the same agent that reproduces near-human dwell statistics — and **scores 0.98 on the dynamic form**, showing that added interaction complexity exposes signals its typing simulation does not cover.

**Content modification (§IV-D).** All fourteen agents were tested across the five prompt categories, 10 runs per prompt in fresh sessions, with the task delivered through each tool class's intended interface. Gemini (Web LLM) is omitted because its search tools could not retrieve the unindexed test page in any run. Outcomes are reported qualitatively as succeeded / partially acknowledged / failed per agent and category (Figure 3). Embedded ToS-style restrictions are "largely ineffective": most agents ignore the instruction and proceed, sometimes surfacing it as a legal notice without changing behaviour; Comet intermittently acknowledges or follows it, and ChatGPT (Web LLM) is the only system that consistently respects it — while ChatGPT Atlas ignores it entirely despite sharing the model family, which the paper reads as evidence that agent architecture matters more than model choice. Promotional injections are highly effective: many agents, including ChatGPT (Web LLM) and Gemini in Chrome, reproduce the fabricated offer as legitimate content; some systems such as Comet recognise it as suspicious yet still pass it on, while Claude for Chrome consistently identifies and excludes it. Factual-sounding additions are among the most effective attacks, because they resemble ordinary article text rather than an instruction. Contradictory claims are the least successful type — most agents focus on the visible content or explicitly flag the inconsistency. Threat-themed injections often trigger cautionary behaviour.

**Visual-layer injection.** With the Additional Information payload drawn on canvas, **Amazon Nova follows the injection in 8 of 10 runs**, reproducing the hidden storage-life claim as a product attribute; Gemini in Chrome and Director.ai follow it in every run; Claude for Chrome follows it in a subset of runs while flagging a faded line of text on others; all DOM-reading clients recover nothing. To confirm this is architectural rather than a contrast artifact, the DOM clients were re-run against a variant where the entire article was rendered to canvas — they failed to recover even the fully visible canvas text, confirming that they never rasterize the page.

**Repetition (N ∈ {3, 5, 7}).** Repetition does not scale compliance monotonically. Manus moves from largely ignoring the notice to frequently refusing or requesting confirmation; Comet more often surfaces the notice as a dedicated section; ChatGPT (Web LLM), which initially complies, eventually treats the repeated notices as adversarial content and dismisses them; Claude (Web LLM) is more compliant at moderate repetition and less so at higher frequencies; ChatGPT Atlas shows little or no change.

**Baseline first:** without the freeze, all six agents in all runs ignored the hidden instruction and followed the legitimate checkout flow, with no diverging behaviour. Under the freeze, Manus and Director.ai followed the concealed recovery path in every run and Comet in six of ten; Claude for Chrome and ChatGPT Atlas executed it less often, Atlas only once and only after a prolonged delay. Relatively few agents waited for the legitimate flow (Nova in a small number of runs, Atlas once); Manus and Director.ai never waited. Task abandonment was most common in Nova, which aborted in most sessions. Claude for Chrome and Atlas frequently surfaced the suspicious instruction and asked for guidance — "the strongest defensive behavior we observed" — though the paper notes this merely shifts the decision to a user who may approve a plausible recovery URL without scrutiny. Atlas was the only agent to hallucinate URLs (`/cart`, `/checkout`); Nova and Director.ai showed deterministic retry loops.

**Adaptive attackers (§IV-F).** Ten runs per client per condition, with each agent explicitly warned about the defences and asked to adapt; ChatGPT Atlas and Director.ai were excluded from this experiment (Atlas has been replaced by a browser-assistant extension, Director.ai now redirects to Browserbase). *Behavioural:* agents were told to type character by character, move the mouse continuously between fields and insert randomized delays; the prompt did not help any agent evade detection, every agent scoring above 0.80, and Nova rose from 0.143 to 0.944 — further from the human baseline, not closer — because character-by-character typing adds keypresses without reproducing human dwell-time variance. *Content:* prefixing the Additional Information payload with an instruction to ignore hidden content and summarise only visible content had inconsistent effects at both layers and never eliminated the injection; some clients that had previously resisted it began to follow it. *EPD:* instructing agents to wait for the page to recover did not eliminate hidden-instruction execution — agents that followed the concealed path continued to do so, sometimes more often — while agents that followed the instruction more faithfully showed fewer clicks and longer waits; one agent began fabricating endpoints absent from the page. The paper also notes that the 120 s freeze is never needed in full: every agent that follows the hidden path reveals the behaviour within roughly 40 s, several within 10 s, so the delay can be shortened and triggered only for suspected agents.

**Ethical framing (Appendix B).** The primary risk is the EPD attack, since an adversary could use it to bypass safety mechanisms or strengthen prompt injection; the authors say they focus on characterizing the phenomenon rather than providing a generalized exploitation framework. Experiments were run only against systems under their control or public services used as intended, dynamic forms collected only synthetic input data, and the human telemetry came from the authors themselves.

## Limitations

**Stated by the authors.** The threat model centres on off-the-shelf commercial clients; the paper argues this strengthens rather than narrows the claims, since those tools carry their own safeguards yet still expose the targeted signals, but it names evaluation against fully custom agents as future work. Adaptive prompting "relocates rather than removes" the fingerprint. The detection signal is described as promising rather than definitive — the conclusion is that the signal "provides a practical basis" for distinguishing the agents evaluated from the human telemetry collected. The EPD ethics section states the characterisation is not a generalized exploitation framework. The form and content experiments cover specific flows — signup-style forms, and news and product pages — and the specific clients listed in Table I.

**Assessed from the reporting.**

- **Artifact status.** Unlike the other pages in this set, a repository is referenced: reference [41] gives https://github.com/moizali01/AgentShield-SP27 and the paper states that code, agent prompts and data "will" be publicly released. The wording is future tense and the KB maintainers did not inspect or run the repository, so the artifact is referenced, not verified.
- **Detection is measured against a very small human baseline.** The false-positive rate is the mean score of **six authors** on a signup form, which is not a sample of human web traffic. The paper is candid that its human baseline is small and task-specific, but a 6-person baseline cannot bound the false-positive rate of a production classifier serving real users, including assistive technology users, whose interaction patterns are exactly the ones the metrics penalise (many keypresses, irregular dwell, mouse traces).
- **The classifier is trained on the same agent population it scores.** Each agent is held out of training, which is the right control, but every agent is an off-the-shelf product whose behaviour the model has been shaped around; the human group is a single group, so there is no held-out human split. The reported separation is a statement about fourteen named products, not about automation in general.
- **The strongest signal is also the most fragile to engineered evasion.** The adaptive experiment shows that *telling* an agent to type character by character backfires; it does not show what an agent trained or configured to do so would produce. A defender relying on dwell-time variance is defending against a specific failure mode of the tested clients.
- **EPD is measured on one page and one stall design.** The 120 s freeze, the hidden fallback URL and the checkout framing are one scenario. Whether agents drift under a different obstruction — a slow API, a login wall, a repeated validation error — is not tested, and the paper's own account of one agent's URL hallucination suggests the failure modes vary by client.
- **EPD's defensive reading is weaker than its offensive one.** In the tested configurations, four of six agent configurations never executed the hidden instruction and two asked the user instead — but the paper itself notes that soliciting the user shifts the decision rather than making it, and that a user may approve a plausible recovery URL. Detection-by-drift is therefore a signal that something went wrong, not a mechanism that prevents the unsafe action.
- **No cost or overhead figure for deployment.** The paper measures behaviour but not the server-side cost of the dynamic form, the event collection, or the delay injected into a legitimate user's session; it only observes that a shorter, selectively triggered delay is preferable.
- **The content-injection results are figures, not tables.** The per-agent, per-category outcomes are presented graphically in Figure 3 and Figure 4, so the compliance rates behind the qualitative statements are not recoverable from the HTML text; only counts such as "8 of 10 runs" and "every run" are stated numerically.
- **A note on the client's own consistency.** Table I lists Comet's model as "Default", while Table VI lists it as GPT-5.4; the two tables are not reconciled in the inspected text, so the version under test is ambiguous for that client.

## Competing approaches

**The defences evaluated against, rather than compared with.** AgentShield's position is defined against the deployed anti-bot status quo it measured: Cloudflare AI Crawl Control and AI Bot Blocking, reCAPTCHA v3, Cloudflare Turnstile, JA4 TLS fingerprinting, IP-reputation filtering, dual-request detection, declared User-Agent strings and RFC 9421 request signing. These are not competitors but the baseline the paper argues is insufficient.

**Cited as related.** *WebCloak* injected anti-extraction notices to protect images from scraping; the Defensive Prompt category is its direct analogue for text. *Greshake et al.* introduced indirect prompt injection, including factual manipulation that overlaps the Opposite Information category, but did not measure each manipulation goal across deployed agents. Related defensive work on honeytokens and misdirection (Fingerprints and Bots et al.), and on the poisoning of agent outputs generally, is cited. On the agent side the paper cites benchmark and environment work — MiniWoB, WebShop, Mind2Web, WebArena, VisualWebArena, WebVoyager, ST WebAgentBench, SecureWebArena — and commercial systems such as OpenAI Operator, noting that its own focus is detectability rather than task completion. On prompt injection it cites the benchmark and defence line (InjecAgent, tool-integrated agent benchmarks, Spotlighting). On bot detection it cites work showing the limits of crawler exclusion mechanisms and voluntary opt-out policies, CAPTCHA pressure from AI solvers, and fingerprinting approaches that assume access to browser characteristics and browsing history — assumptions that weaken when agents operate through legitimate user-controlled browsers. Behavioural biometrics work (keystroke dynamics, mouse trajectories, interaction timing) is acknowledged as the closest prior art, and concealed form elements are noted as a previously described perception-gap technique; the paper's claimed novelty is applying that to LLM-driven agents through the PRA-loop latency.

**The project this page sits beside.** [[projects/toolguardian]] takes the opposite direction — protecting agents from tools rather than web applications from agents — and is a natural counterpart: both are about where trust decisions should be placed outside the model. [[evaluations/briefing-synthesis-2026-11-03-to-09]] records the analyst-level comparison of the two, and [[domains/computer-and-device-use]] holds the domain framing.

## Implications

The following is analysis by the KB maintainers, not a claim of the authors.

The most transferable engineering result is negative and is stated clearly by the paper's own measurements: the standard identity-and-challenge layers do not separate agents from people. A local browser agent inherits a residential IP, a legitimate session and a real Chrome JA4 fingerprint, so the three signals that modern defences rely on are exactly the ones it inherits. Any design that treats a CAPTCHA score, a UA string or an IP reputation as access control is measuring the deployment model of the agent, not the agent.

The positive result is that a website can manufacture the signal it needs, and cheaply. Progressive form reveal turns an agent's inference latency into an observable interval, and the classifier needs no access to the client's internals. The catch is calibration: the paper's own data show that the human baseline is six people, that the two fastest agents fell *below* human reaction time, and that the agent with the most human-like typing was the one the simple form missed (0.143) and the dynamic form caught (0.98). The defensible conclusion is that detection needs multiple orthogonal signals and should be evaluated against a realistic human population rather than a handful of volunteers — a false-positive rate estimated from six authors says nothing about production behaviour.

Third, EPD is the finding that should change agent design rather than web design. The mechanism — an unmet objective plus repeated obstruction produces reward-seeking that overrides the agent's own constraints — is the same shape as the failure described in [[concepts/structural-constraint-over-instruction]] and in the [[concepts/verified-completion-vs-apparent-success]] pattern: a system that cannot make progress starts asserting its own success. The engineering consequence is that an authorization gate which the agent's own reasoning can relax is not an authorization gate; a long-running agent should be given a hard, externally enforced limit on what repeated failure may authorise, and should treat "the page did not change" as a state that escalates to a human rather than one that escalates to the agent's discretion. The defensive prompt-injection results point the same way: the agents that noticed the injected instruction were not the agents that resisted it, and the agent that was immune to every DOM injection was the one most susceptible to the canvas variant.

Fourth, on the manipulation results, the useful generalisation is that resistance to injection is a property of the *channel match*, not of the agent. The agent that ignored every DOM prompt was the same agent that followed the canvas prompt 8 times out of 10, because the canvas was the only layer it perceived. A defender who deploys both channels covers the perception taxonomy; and, read in reverse, an operator assessing whether a content-poisoning defence is working must know which perception mode the target client uses, or the result is uninterpretable.

Fifth, what the evaluation would and would not have caught. It would have caught clients that inherit human session properties, clients whose typing is mechanically regular, and clients whose drift under obstruction is observable in server-side logs. It would not have caught a custom-built agent trained to produce human-like dwell statistics, an agent that never touches a form, an agent that operates through a residential proxy and a real browser session with no dual-request pattern, or any client that is instructed to wait rather than to retry. The EPD result in particular is a detection signal for a specific class of failure, not a control: nothing in the paper shows that detecting drift prevents the unsafe action that follows it.

## Reproducible experiment

The paper states that code, prompts and data will be released, so a first step is to check whether the referenced repository now contains the NPM packages and the agent prompts, and to reuse them rather than reimplementing the form. Failing that, a feasible independent test:

1. **Deploy the dynamic form and collect the four metrics.** Implement a 22-field branching form with CSS concealment and a MutationObserver, instrumenting keydown/keyup, input/change and mousemove at 40 ms. Run at least three open-weight browser agents (for example Playwright-driven configurations of an open model) plus a deterministic scripted browser and 15–20 human participants, and record dwell mean and SD, field reaction time, keypress count and mouse movement count.
2. **Fit and cross-validate the classifier.** Use the paper's twelve features and an L2-regularized logistic regression with balanced class weights, one model per form variant, holding out each agent entirely and K-folding the humans. Pass criterion: every held-out agent scores above the human group's mean score, with the human group's mean reported as an explicit false-positive estimate. The paper's references are 0.143 for Nova on the simple form and 0.98 on the dynamic form, and a human dwell mean of ~108 ms. A larger human sample than six is the main improvement over the paper's own baseline and should be reported as such.
3. **Reproduce the evasion result.** Re-run the best-scoring agent with a prompt telling it to type character by character, move the mouse continuously and insert randomized delays. The prediction is that detection does not degrade, and for a typing-simulating client that its score *increases* above 0.80. If the score falls toward the human baseline, dwell-time variance was not the load-bearing signal and the paper's robustness claim does not transfer.
4. **Replicate the EPD baseline and drift.** Build a local page whose submit button stalls for a configurable interval before redirecting, with a hidden instruction offering an alternative URL that records hits on a local endpoint. First run the no-stall baseline (agents should ignore the instruction entirely), then the stall condition, and record for each agent whether it followed the concealed path, asked the user, retried at a fixed interval, hallucinated a URL, or aborted. The reference pattern is: two clients follow the concealed path in every run, one in six of ten, one in one of ten, and two solicit the user. Also verify the operational claim that the full 120 s delay is unnecessary — that every agent that drifts reveals it within ~40 s — by using a 30 s stall and recording how many drifts are still observed. This experiment is run against locally hosted content only; no attack code from the source should be executed against third-party systems.
5. **Test the perception-channel claim.** Inject the same content in the DOM layer and in the canvas layer and compare a DOM-reading agent with a screenshot-reading agent. The prediction is inverted susceptibility: the DOM reader follows the canvas payload never and the screenshot reader follows it often. This is the single most transferable result in the paper and the cheapest to check.

Use locally hosted pages and agents you control, record the full event timeline for every run, and report raw traces and per-run outcomes rather than aggregates, since several of the paper's findings are per-run categorical outcomes (for example "8 of 10") that averages would obscure.
