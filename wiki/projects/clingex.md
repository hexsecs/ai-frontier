# ClinGeX

## What it is

ClinGeX is a clinical-genomics agent built around a library of 105 curated, executable *skills* rather than around a single monolithic prompt or a generic tool list. Each skill is a reusable, version-controlled instruction module — a `SKILL.md` file specifying when it should be invoked, what information to seek, which standards and resources to consult, which tools to call, and a step-by-step workflow, optionally accompanied by scripts, references, and assets. A skill encodes one atomic clinical-genomics operation: following a named guideline, mapping an entity between nomenclatures, looking up a data source, performing a numerical calculation, or running a model-based prediction.

The paper reports three evaluations, and they are different kinds of evidence. The first is an automated benchmark on 223 temporally held-out cases (the only evaluation in the paper to which "held-out" applies). The second is a randomized, three-centre human–AI collaboration study with 45 clinician readers and 135 retrospectively collected cases. The third is a one-month, non-interventional deployment in which 11 senior professionals used the system on self-selected routine tasks and reported back. All three were designed, executed, and adjudicated by the authors' own institutions; every result on this page is author-reported, and none has been independently replicated.

The system's stated purpose is to augment specialist clinicians working on variant interpretation, gene–disease validity assessment, and clinical actionability — the three task families its evaluations cover.

## Mechanism

**Skill library.** The 105 skills are organised along two axes that deliberately do not coincide. By construction action type there are 27 guideline-following, 13 entity-mapping, 30 data-source-lookup, 12 numerical-calculation, and 23 model-based-prediction skills. By deployment class these regroup as 27 guide, 40 search, and 38 analysis skills.

**Construction pipeline.** The library was built in stages. A web-scale resource scan (frozen 28–30 July 2026) harvested candidate resources at scale — for data-source lookup alone, 45,364 catalogue records from the NAR Database Issue index, bio.tools, re3data.org, and FAIRsharing resolved into 41,000 linked resource clusters; across all categories the scan produced 195 guideline documents, roughly 3,500 entity-mapping candidates, 53 calculation methods, and 205 predictor records consolidated to 144 models. An LLM scored candidates against category-specific rubrics (quantitative categories on a weighted 0–100 scale with tier thresholds; guidelines assessed qualitatively, deliberately without scores), but the tiers only prioritised review — final inclusion was by consensus of eight clinical experts from seven institutions, who could retain lower-tier candidates that filled gaps or drop redundant higher-tier ones. The output was 105 frozen prototypes.

Each prototype was then compiled by a builder–evaluator loop. A builder agent based on DeepSeek-V4 produced the `SKILL.md` package; a separate evaluator generated 5–20 skill-specific test cases spanning valid, boundary, alternative-representation, batch, non-applicable, absent-record, malformed-input, and simulated external-failure inputs; an execution agent ran them through the same action interface used at run time. Failures were summarised and returned to the builder for revision, repeating until all identified failures resolved or five revision cycles were reached. Only skills passing all frozen tests entered the deployed library.

**Skill graph and retrieval.** All 5,460 unordered pairs of skills were scored by GPT-5.5 on five relatedness dimensions (purpose similarity, input overlap, substitutability, complementarity, joint use; each 0–4, summed to a weight R in [0, 20]), with a categorical dependency label; the result included 28 directed prerequisite edges. At inference time, a fixed DeepSeek-V4-Flash decomposition step turns each user message into one to three concise analytical needs; each need is embedded (Qwen text-embedding-v4) and cosine-scored against precomputed embeddings of every skill's scope fields. The top 30 skills form a seed set, expanded by one-hop neighbours with R ≥ 8 (capped at 15 additions; three literature/web search skills are always included), followed by prerequisite closure to a fixed point. This is progressive disclosure: the host agent sees only concise descriptions of the selected skills, plans a workflow, and spawns sub-agents per step that load the full skill instructions and execute — a plan–execute orchestration. Multimodal inputs are normalised first (PDFs to Markdown via MinerU; images such as pedigree charts summarised by Qwen3-VL).

**Agent core.** The headline results use DeepSeek-V4 (`deepseek-v4-pro`) as the agent core, chosen in a controlled comparison against Qwen3, GLM-5, GPT-5.4-Pro, Claude-4.6-Opus, and Gemini-3-Pro on 3,662 evidence-grounded QA items. The per-model results of that selection experiment are presented only as radar plots (see Limitations).

## Evidence

### Automated benchmark — 223 temporally held-out cases

The benchmark cases are expert-curated records released or substantively updated after October 2025 — after the training-data cutoffs of all evaluated models — drawn from ClinVar/ClinGen (single-nucleotide-variant interpretation, n=79; gene–disease validity, n=66) and from CIViC, OncoKB, and PharmGKB/ClinPGx (clinical actionability, n=78). Every system received the same processed literature bundle per case; direct access to the five source databases was prohibited; reference answers were inherited from the versioned source records and reviewed by three physicians. The primary metric, final-answer concordance, was computed by deterministic rule-based scoring from frozen structured outputs — no LLM judge decided whether a final classification matched the reference.

ClinGeX (DeepSeek-V4 core, 105 skills) achieved 71.7% macro-averaged concordance across the three tasks, compared with 45.7% for the strongest comparator — a 26.0-percentage-point margin. Per task, ClinGeX reached 89.9% on SNV interpretation (best baseline: DeepResearch, 49.4%), 53.0% on gene–disease validity (best baseline: Biomni, 35.5%), and 72.3% on clinical actionability (best baseline: TxAgent, 52.3%). Denominators differ by endpoint: the actionability figure, for example, is computed over the 65 tier-applicable cases rather than all 78, and the SNV sensitivity/specificity figures (100% and 92.4%) exclude VUS references from their binary denominators. Repeat consistency across tasks was 87.9–93.7%, and mean execution time (175–197 s) was broadly comparable to other agentic systems. An LLM audit of execution records found no case of ClinGeX retrieving substantive case-specific information from the corresponding reference resource (0/79, 0/66, 0/78), while several comparators showed small non-zero rates.

A blinded review adds a qualitative layer: nine domain experts rated de-identified reports from ClinGeX, Biomni, and DeepResearch (669 reports; each case's three reports rated by a single reviewer, so inter-rater agreement was not estimated). The proportions receiving the highest overall-acceptability rating were 88.6%, 66.7%, and 67.9% for ClinGeX across the three tasks, against 32.9–40.9% for DeepResearch and 17.9–43.9% for Biomni; 74.9% of ClinGeX reports were judged directly adoptable without substantial revision. In the actionability task, however, citation-accuracy and fabrication-avoidance ratings were similar across systems — ClinGeX's clearest advantages were acceptability, guideline adherence, and evidence completeness.

### Architecture ablation

To isolate what the skill architecture adds over the same base model, the authors compared seven conditions, all with the DeepSeek-V4 core held fixed, on 426 evidence-grounded QA items. These items were generated by DeepSeek-V4 from source records, and responses were scored by two LLM judges (GPT-5.5 and Claude-4.8-Opus) against item-specific rubrics — so this is an LLM-judged result on model-generated items, a weaker form of evidence than the rule-scored benchmark above. The full ClinGeX architecture scored 83.2%, versus 72.2% for plain DeepSeek-V4 and 74.0–78.4% for the five single-strategy conditions (retrieval-augmented generation with the search-skill bundle, few-shot prompting, multi-agent planner–executor–reviewer orchestration, and two third-party skill libraries, BioSkill and MedSkill). The largest separation occurred on the hardest reasoning tier.

### Randomized MRMC human–AI study

The controlled human study was a randomized, three-centre, multi-reader multi-case (MRMC) study: 45 readers (15 per scenario, 3–10 years of relevant experience) each completed 9 of 135 retrospectively collected real-world cases, with every case assessed under all three conditions by three different readers and condition order randomized and counterbalanced. The conditions were routine practice (usual resources and internet, no AI tools), assistance from DeepSeek through its official consumer web interface, and assistance from the deployed ClinGeX platform. The primary outcome, case-level concordance, is a strict composite: assessments were adjudicated by a three-member expert panel per scenario as substantially correct only under scenario-specific rules (in the variant-analysis scenario, for instance, the exact five-tier class plus every reference ACMG/AMP criterion recovered, each at a strength within one adjacent level). These figures are therefore not plain accuracy and should not be compared directly with accuracy numbers from other tools.

Observed concordance under ClinGeX assistance was roughly double routine practice in all three scenarios: 51.1% vs 22.2% for criterion-level variant analysis, 57.8% vs 28.9% for genomic interpretation in rare disease, and 64.4% vs 31.1% for molecular oncology decision-making. The GLMM-standardised differences against routine practice were 29.9, 29.6, and 33.4 percentage points respectively (Holm-adjusted P = 0.013, 0.017, 0.002). Against DeepSeek-chat assistance the differences were also significant — and the comparison contains the study's most uncomfortable finding, which this page reports plainly: DeepSeek assistance scored *below* unassisted clinicians in two of the three scenarios (15.6% vs 22.2% in variant analysis; 20.0% vs 31.1% in molecular oncology), and only slightly above routine practice in the third (31.1% vs 28.9%). Secondary outcomes were directionally consistent — higher evidence recall, fewer unsupported-evidence assignments, better evidence-strength concordance — though not all contrasts reached significance, which the authors attribute to the study being powered for the main effect. Reported time per case fell (median 60 to 15 minutes in variant analysis; 30 to 15 in rare disease; 15 to 11 in oncology, the last not significant), but these times are readers' post-study estimates, not measured task times.

### One-month deployment

In a prespecified one-month deployment, 11 senior professionals (each responsible for more than 500 case reports per year, from five centres, none from the MRMC study) used ClinGeX on self-selected routine tasks and filed a structured feedback record per completed episode: 96 episodes. The deployment was explicitly non-interventional — ClinGeX outputs were not permitted to influence clinical reports, patient management, or any other clinical decision. Participants rated the system's conclusion as fully adoptable in 72.9% of episodes and partially adoptable in 21.9% — 94.8% full or partial adoption — and reported time savings and high helpfulness ratings across information standardisation, numerical analysis, literature analysis, and procedural guidance. A post-hoc check against platform logs put feedback coverage at a lower bound of 86.5% of conversations. This study is uncontrolled and entirely self-reported, and "adoption" here means a professional's stated intent regarding an output that was barred from entering any clinical record — it is workflow feedback, not outcome evidence.

## Limitations

- **Nothing here is independently reproducible at present.** The ClinGeX source code is not public — §6 of the paper offers only a registration-gated hosted demo (a Chinese–English bilingual deployment) — and the data are available only on request to the corresponding authors. External verification of any number in the paper is currently impractical.
- **Single-team evidence.** The benchmark, both human studies, the adjudication panels, and the report raters were all run or recruited by the authors' institutions. No independent replication of any result is reported.
- **Agent-core selection is not numerically checkable.** The experiment that selected DeepSeek-V4 as the core reports per-model scores only as radar plots in Extended Data Fig. 1e; the numbers cannot be extracted from the text, so the margin by which the chosen core beat five alternatives cannot be verified or quoted.
- **Benchmark home field.** The 223 held-out cases are drawn from exactly the five resources whose procedures the skill library was purpose-built to encode, and every system was handed the same curated literature bundle needed to reconstruct the reference answer. The temporal holdout blocks memorisation of the specific records, but general-purpose comparators faced a task distribution aligned with ClinGeX's design centre, and real-world cases do not arrive with pre-assembled evidence bundles.
- **Denominator heterogeneity.** Headline percentages are not on common denominators: actionability concordance uses 65 of 78 cases; gene–disease scoring uses each system's own parsable-output subset; SNV sensitivity and specificity exclude VUS references. Cross-task and cross-system comparisons need the supplementary denominators, not the raw percentages.
- **Comparator asymmetries.** SciSpace's backend model is undisclosed and could not be independently configured; OpenBioLLM-70B is a non-agentic domain LLM included among agent systems; DeepResearch was capped at 30 native tool calls; Biomni and TxAgent were re-based onto DeepSeek-V4 rather than run in their original published configurations. In the MRMC study, the comparator arm was a consumer chat interface, while the ClinGeX arm was a purpose-built platform — the assistance effect bundles interface, retrieval, and content.
- **Author-stated limits.** The MRMC study covered only three scenarios, selected around the participating centres' specialties; its primary endpoint is a proxy — concordance with expert consensus reflects interpretive quality rather than patient outcomes, and the authors state that establishing clinical benefit will require a prospective randomized trial with prespecified clinical endpoints. The deployment measured workflow-level outcomes (adoption, time saved, perceived helpfulness), not diagnostic yield, management changes, or patient outcomes. Several secondary MRMC comparisons did not reach significance. Blinded report ratings used a single reviewer per case, so inter-rater agreement is unknown.
- **Model-mediated evaluation stack.** DeepSeek-V4 is simultaneously the skill builder, the deployed agent core, and the generator of the ablation items; GPT-5.5 scored the skill graph and co-judged the ablation. This does not invalidate the results, but the evaluation is heavily model-mediated, and the ablation's items and judges are not independent of the systems being compared.

## Competing approaches

The benchmark's head-to-head comparators were OpenAI DeepResearch (o3-deep-research, a commercial general-purpose research agent), Biomni (an open-source biomedical agent, run as A1 with its tool retriever), TxAgent (an open-source therapeutic-reasoning agent over ToolUniverse), SciSpace (a commercial literature-research system with an undisclosed backend), and OpenBioLLM-70B (a domain-specialised LLM without an agent framework). In the MRMC study the assistance comparator was DeepSeek's consumer chat interface. The ablation supplies the design-level competition: retrieval-augmented generation, few-shot prompting, multi-agent planner–executor–reviewer orchestration, and two third-party skill libraries — BioSkill and MedSkill — which are the closest named competitors to ClinGeX's skill-centred design and scored in the same 74.0–78.4% band as the other single-strategy conditions. Six agent cores were compared during system development (DeepSeek-V4, Qwen3, GLM-5, GPT-5.4-Pro, Claude-4.6-Opus, Gemini-3-Pro). The paper's background positions conventional single-step bioinformatics tools (such as Ensembl VEP and Exomiser) and tool-augmented LLM database access (GeneGPT) as the non-agent status quo.

## Implications

For agent design, the paper is evidence — from a single team, under the caveats above — that a curated, individually tested skill library with dependency-aware retrieval can outperform both a plain frontier model and generic enhancement strategies (retrieval, few-shot examples, multi-agent orchestration) on the same base model, and that third-party skill libraries used off the shelf did not match a library built and test-filtered for the domain. The construction method matters to that claim: skills entered the library only after passing frozen, skill-specific test suites generated to include malformed, absent-record, and failure cases, which makes the library closer to a tested codebase than to a prompt collection.

For evaluation practice, the study is a useful template and a useful warning. The template: a temporal holdout defined against model training cutoffs, deterministic rule-based scoring of final answers rather than LLM judging, a leakage audit of execution records, and a randomized multi-reader study whose primary endpoint is a strict, adjudicated composite. The warning: the same paper shows how easily headline numbers detach from their denominators, how a comparator arm's interface can dominate its content, and how an abstract's compressed comparator figures (the abstract's MRMC triple is the DeepSeek arm only, not routine practice) can mislead a skim reader. The finding that a general-purpose chat assistant scored below unassisted specialists in two scenarios — while a domain-built platform roughly doubled concordance — is, if it holds up, an argument that assistance quality is a property of the whole workflow system, not of the underlying model alone.

## Reproducible experiment

A full reproduction is not currently possible from public materials: the code is registration-gated and the data are on request. What an independent team *could* do, following the paper's published methods, is a partial replication of the benchmark arm. Construct a fresh temporal holdout by sampling expert-panel records from ClinVar/ClinGen, CIViC, OncoKB, and PharmGKB released or substantively updated after the training cutoffs of every model under test, stratified to the paper's class distribution (79 SNV, 66 gene–disease, 78 actionability cases); withhold the ground-truth fields; give every system the same processed literature bundle per case with direct database access prohibited; and score final answers by deterministic rules from frozen structured outputs, reporting per-endpoint denominators explicitly (including the tier-applicable subset for actionability and the exclusion of VUS references from sensitivity/specificity). The architecture ablation is more accessible: its 426 items, seven conditions, and dual-LLM-judge rubric protocol are described in the supplement, and the two third-party skill libraries it uses (BioSkill, MedSkill) are public repositories, so the skill-architecture comparison could be re-run against a different base model — though the original item set itself is among the on-request data. The MRMC study design (45 readers, 135 cases, three conditions, Latin-square counterbalancing, expert-panel adjudication under strict composite rules, GLMM analysis with Holm correction) is specified in enough detail to be re-run at other centres, and an external MRMC replication would address the single-team limitation more directly than any benchmark re-run.

## Evidence status

All results on this page are **author-reported** from a single arXiv preprint (arXiv:2610.40556, submitted 29 October 2026) and its supplement, read in full for this page on 2026-11-02. No independent replication, third-party benchmark, or vendor-neutral evaluation of ClinGeX is known to this KB. The paper's primary source was inspected directly; the ClinGeX code was not inspected (it is not public), no benchmark was reproduced, and the agent-core selection scores could not be extracted numerically because they are published only as radar plots. The earlier import of this page, which described the evidence as unverified briefing material, is superseded by this treatment.
