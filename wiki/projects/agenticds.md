# AgenticDS

## What it is

AgenticDS is a contract-governed agentic framework for searching million-scale machine-learning repositories — in the paper's experiments, Hugging Face — for datasets that satisfy a training need. It comes from Qiaosheng Chen, Kaijia Huang, Fanqi Zhou, and Gong Cheng at Nanjing University (arXiv:2610.39608, submitted 29 October 2026), and it was released together with HuDS-Bench, a 200-query benchmark for dataset search over a Hugging Face knowledge graph. The implementation and the benchmark data are public under Apache-2.0.

The problem the paper addresses is that dataset search is not ordinary text retrieval. A real training-data request couples a semantic goal with typed constraints — task, modality, language, license, training stage — and the metadata that would verify those constraints is often missing from dataset cards. Flattening the request into a single embedding makes constraint violations invisible; free-form tool-calling agents are no better, because, in the paper's words, "the same model that selects a dataset also declares it a match." A third gap is that retrieval relevance does not by itself entail training utility: standard benchmarks never check whether the datasets a system selects actually improve a downstream model.

AgenticDS answers with three design principles — "contracts before actions," "provenance before fusion," and "bounded autonomy." Its core design claim is that in this framework "every language model decision instantiates a typed object before deterministic code consumes it": three LLM roles (Planner, Engineer-facing protocol, Critic) exchange typed plans, protocols, evidence packages, and diagnoses, while only deterministic code touches the retrieval index and the knowledge graph. The paper's second research question then closes the loop its title promises: a search-to-train study tests whether the datasets AgenticDS retrieves measurably improve fine-tuned models. All quantitative results below are author-reported; none has been independently replicated.

## Mechanism

The search runs as a bounded loop of up to T rounds (T = 3 in the main configuration). Each round, a Planner emits a typed plan, an Engineer compiles the plan into an action protocol and executes hybrid retrieval plus typed knowledge-graph expansion, and a Critic reviews the fused candidates and returns a ranking with feedback. The system retains the round that maximises a utility function and stops when the Critic accepts, when two consecutive rounds bring no utility improvement, or when a critical diagnosis recurs in consecutive rounds.

**Planner — the typed search plan.** The plan is a tuple: several query branches, each grounded in the original request with a stated evidence purpose; the declared one- or two-hop graph paths that expansion may follow; hard constraints versus soft preferences; the intents a candidate should jointly support; bounded pool slots reserved for selected branches, so broad text matches cannot crowd out provenance-specific candidates; and quality, intent-coverage, and minimum-count acceptance thresholds. Branches are marked *direct-retrieval* (candidates from the dataset index — one branch always keeps the original user query verbatim, "preserving joint semantics that decomposition may separate") or *graph-expansion* (candidates reached from entity anchors — datasets, models, papers, or collections — over the declared paths). On later rounds the Planner performs only local repair: it reads the previous plan, the Critic's feedback, and the set of already-executed branch signatures, preserves the original requirements, and adds queries that address diagnosed gaps; it ends the search when it has no new branch signature to try.

**Engineer — deterministic execution only.** The Engineer compiles the plan into a protocol of predefined operators with bounded anchor, neighbour, and pool budgets, and allocates retrieval effort adaptively per branch. Each entity gets a dense score combining cosine similarity to its description embedding and its metadata embedding (separate FAISS indexes; Lucene provides BM25), fused with the sparse rank by reciprocal rank fusion. Typed graph expansion follows only the paths the Planner declared; a dataset's relation score sums over all permitted anchor-to-dataset paths, weighting each anchor's hybrid score by a name/identifier match confidence, a per-hop decay, and a per-edge degree penalty, so widely connected entities contribute less support. Candidate lists from all branches and rounds are archived and fused by group-normalised reciprocal rank fusion — lists are grouped by evidence purpose and weights normalised within each group, so issuing more queries cannot disproportionately increase one group's influence. Constraint pre-ranking then discards candidates with *explicit* hard-constraint violations, while missing fields stay "unknown" and are not rejected: "Missing metadata or graph links indicate unknown support, not irrelevance." Surviving candidates rank by a blend of fused score and soft-preference utility (with log-saturation for counts such as downloads and likes), and the Critic pool is drawn from this ordering under the Planner's slot reservations. Every candidate retains its branch ranks, fusion contributions, constraint status, anchors, and paths — an audit record rather than a single collapsed score.

**Critic — evidence scoring, acceptance, typed diagnosis.** For each pooled candidate the Critic receives a fixed-format, four-part evidence package: concise card excerpts, normalised metadata, sample fields and instruction–response snippets when available, and retrieval plus graph provenance — with text, metadata, content, and graph support kept separately inspectable. It returns a semantic score for joint satisfaction of the query requirements, blended with the pre-ranking score into the final score that orders the round's ranking. Its feedback record carries an acceptance flag; a ranking-quality term (the mean final score over the top quarter of results); an intent-coverage term (the maximum fraction of intents jointly supported by at least one dataset in the top half — joint support matters because "a Python corpus and an unrelated instruction corpus cannot jointly establish instruction–response pairs for Python coding"); and typed diagnoses naming a failure code and severity, the affected intents, the supporting evidence and confidence, and the permitted local repair. Acceptance requires the quality and coverage thresholds to be met, the minimum result count reached, and no unresolved critical diagnosis; otherwise the diagnoses permit only local plan repairs in the next round. Because the Planner fixes the branches and the Engineer may run only declared operators, the authors note, "a module can be disabled while everything downstream of it behaves as before, which is what makes component-level ablation well defined."

**Infrastructure.** The experiments run over a 12 March 2026 snapshot of HuggingKG (Chen et al., SIGIR 2025), comprising 4,928,681 entities — 910,119 of them datasets — and 3,951,507 relations, including model–training-dataset and collection-membership edges. The paper adopts the graph "as auxiliary infrastructure rather than as a contribution of this paper." The main configuration uses a GLM-5.2 agent backbone with Qwen3-Embedding-0.6B embeddings and returns up to 20 datasets.

## Evidence

All results in this section are author-reported, from the paper's own experiments; the statistics are the authors' paired permutation and sign-flip tests with Holm correction.

**Retrieval on HuDS-Bench.** The benchmark holds 200 English queries in four types — General (90), Fine-tuning (40), Paper reference (40), and Entity neighbor (30, of which 29 are strictly multi-hop) — constructed from gold datasets' metadata and, for the relational types, HuggingKG anchors. Relevance pools merge the top-20 results of all 15 evaluated systems, giving 24,908 query–candidate pairs labelled by an LLM annotator (DeepSeek-V4-Pro-0813) working from a structured rubric: each constraint is resolved to satisfied, violated, or unknown and deterministically projected to graded labels 0/1/2. Against a 2,490-pair human-annotated sample the pipeline reached 84.1% exact agreement and linearly weighted Cohen's κ = 0.754.

On this benchmark AgenticDS (GLM-5.2 backbone, Qwen3-Embedding-0.6B) reaches NDCG@10 of 0.6148 and leads at every NDCG cutoff: +25.7% over the strongest dense–sparse hybrid (Qwen3-Emb+BM25, 0.4893) and +18.9% over the strongest agent baseline, a Claude Code harness driven by GLM-5.2 (0.5170). The paper states these NDCG margins hold against all fourteen other systems after Holm correction. The advantage roughly doubles on the relational query types (ΔNDCG@10 over the hybrid: Paper reference +0.206, Entity neighbor +0.197) versus the semantic types (General +0.075, Fine-tuning +0.105). The picture is narrower on MAP: AgenticDS posts the best MAP@10 and MAP@20, but its margins there over the two agent baselines do not survive correction (Holm p between 0.13 and 0.45), so the authors "claim an advantage in graded ranking rather than in binary relevance."

**Ablations identify the Critic as load-bearing.** Removing the Critic costs −0.149 NDCG@10, the largest single effect; removing the Planner costs −0.086 and removing graph expansion −0.084; dropping the feedback loop costs −0.036 and the adaptive budget −0.031. The effects are non-additive — removing Planner and Critic together (−0.121) hurts less than removing the Critic alone, because without a Planner the Engineer falls back to wide default retrieval. The authors' verdict: "Verification is therefore the load-bearing component, since every configuration that removes the Critic, alone or in combination, falls below both agent baselines."

**Graph expansion is conditional, not additive.** In a Critic-free variant, graph candidates passed straight into the ranking *lower* NDCG@10 by 0.025–0.029 on every text backbone tested. The same expansion improves results only behind the provenance-aware Critic — the paper's headline framing is that expansion and verification "are not separable features."

**Backbone sensitivity.** Swapping the backbone to Qwen3.5-35B-A3B from a different model family gives NDCG@10 of 0.5244 — still above every baseline — while a weaker backbone (GLM-4-9B) drops the full system to 0.4706, level with plain BM25 (0.4717). The authors conclude that "a frontier-scale Critic is a prerequisite, not an optimization."

**Cost.** Over the 200 queries, AgenticDS billed 12.3M tokens against 111.4M for the Claude Code harness and 280.9M for the Codex harness; priced at one shared GLM-5.2 rate card, totals are $19.86 ($0.099 per query) versus $48.78 and $112.40 — author-reported savings of 59% and 82%, with AgenticDS's figure an upper bound (billed entirely at the uncached rate). Latency is 150.5 s per query, roughly at parity with the Claude Code harness (139.3 s) and 5.8× faster than Codex (868.5 s). Within AgenticDS, the Critic consumes 83.0% of tokens but 28% of wall-clock time.

**Search-to-train utility.** Each method's top-5 eligible datasets per query contribute at most 2,000 samples each to a supervised fine-tuning corpus; only the retrieval method varies, with base model, budget, trainer, and evaluation suite fixed. The grid covers three base models (Qwen2.5-7B, Llama-3.1-8B, Olmo-3-7B-Instruct) across three domains. AgenticDS's retrieved data gives the best downstream averages in all three domains — mathematics 49.82, code 49.62, medicine 59.00 — for a grand mean of 52.81 against 49.75 for the runner-up (the Qwen3-Emb+BM25 hybrid), a +3.06 margin the authors report as significant against each compared method under their primary correction. The margins are uneven, however: mathematics is clear (+3.86 over the next best), while code and medicine rest on +0.41 and +0.49 respectively, and AgenticDS loses two of the nine (domain, base-model) blocks — both in medicine, both to the Claude Code harness, both by under a point. Gains are monotone in base-model weakness: the total improvement over the best alternative is largest for Llama-3.1-8B and smallest for Olmo-3-7B-Instruct — "the weaker the base model, the more acquisition quality decides the outcome." A downstream component ablation largely resolves nothing: the largest effect, removing the Critic (−1.85 mean accuracy points), falls just under the authors' own roughly-two-point separation bar.

## Limitations

**Benchmark circularity (author-acknowledged).** HuDS-Bench's relational half is built from the same HuggingKG that the system traverses: the Paper reference and Entity neighbor queries are constructed from graph anchors the Engineer can also reach by expansion. The authors state this plainly — "benchmark construction shares a graph with the retrieval engine" — and cite mitigations: 130 of the 200 queries carry no KG-derived gold label, non-KG baselines received Hugging Face full-text search, and the no-expansion variant still reaches 0.5307 NDCG@10, above every non-agent baseline. A KG-free gold-label pipeline remains future work.

**The utility study is narrow.** The entire search-to-train result rests on three queries — one per domain — across three base models, with no independent training seeds. The authors caution that their significance tests are "a consistency check across blocks rather than as a measure of how much retraining would move the scores," and that collapsing the test to three domain-level units leaves a smallest two-sided p of 0.25. Query wording is an unexamined degree of freedom, and the sub-half-point code and medicine margins mean the three-domain sweep is thinner than the headline suggests.

**Silver labels, single runs.** The graded relevance labels are LLM-produced, with a same-model second pass over disputed items and human adjudication of residuals; the single κ = 0.754 agreement figure comes from one researcher on a 10% sample and is pooled over query types, although the relational types almost never use the middle grade. Every system contributes a single run, and the authors note that "none of which Holm correction repairs."

**Baseline asymmetry (analyst-assessed).** The LLM-agent baselines are the authors' own harness configurations — Claude Code and Codex driven by GLM-5.2, single-shot, asked for 30 ranked dataset IDs — not the vendors' products as sold, and they were not given iteration budgets comparable to AgenticDS's three-round loop with best-round retention. The 18.9% NDCG gap is therefore a gap to a particular agent configuration, not to agentic search as such; the cost comparison cuts the other way, since those baselines were far more expensive. A related concern (analyst-assessed): relevance labels are produced from the same kind of structured evidence package — card excerpts, metadata, snippets, provenance — that the Critic consumes, which may systematically favour systems whose ranking signal is closest to that representation; the human agreement study does not test this alignment directly.

**Co-design and snapshot dependence (analyst-assessed).** The benchmark's relational types are constructed so that the correct answer is unreachable by lexical matching alone — that is, the hard half of the benchmark is defined around exactly the capability (typed graph traversal) that distinguishes the proposed system, so the +0.206/+0.197 relational gains should be read with that construction choice in mind; the semantic-type gains on 130 queries are the more conservative evidence. All results also come from a single March 2026 HuggingKG snapshot on a single hub; metadata quality and graph coverage drift, and no cross-snapshot or cross-hub evaluation exists.

## Competing approaches

The paper evaluates four families. Platform search — Google Dataset Search and Hugging Face full-text search — trails far behind (HF full-text reaches NDCG@10 of 0.2438). Classical retrieval baselines span sparse (BM25, BM25+RM3), dense (bge-m3, Qwen3-Embedding-0.6B), hybrid reciprocal-rank-fusion combinations, and a retrieval-then-rerank pipeline (monoT5(OOD)+BM25, 0.4923); the strongest hybrid is the runner-up on both retrieval and downstream training. Free-form LLM agents — the Claude Code and Codex harnesses with Hugging Face Hub tools — are the paper's foil for unverified tool-calling, in the lineage of ReAct and agentic information retrieval systems such as Search-R1 and Search-o1, all of which give the LLM direct tool control; AgenticDS's contract discipline is a deliberate rejection of that pattern. The closest prior system is DataFinder (Viswanathan et al., ACL 2023), which recommends datasets from a natural-language research idea via a flat bi-encoder ranking; the paper positions its typed constraints, relational evidence, and training-utility check as the three additions. The benchmark predecessor is ACORDAR / ACORDAR 2.0, public-data retrieval test collections without natural-language training needs over ML hubs. Data-centric self-improvement systems such as DataEvolver and DataFoundry are positioned as downstream complements rather than competitors: they optimise data already in hand, while AgenticDS targets the acquisition step before them. Dataset-quality assessment of the kind in [[projects/exlabel]] is adjacent — it grades datasets that already exist in a corpus, where AgenticDS decides which datasets enter one.

## Implications

The strongest transferable claim is about where the value sits in an agentic retrieval pipeline. The ablations say the typed plumbing is not the active ingredient by itself: expansion without verification actively hurts, the Planner's contribution is partly substitutable by wider default retrieval, and the component whose removal collapses performance below every agent baseline is the Critic — a verifier that reads a structured evidence package, keeps provenance separately inspectable, and issues typed diagnoses that bound what the next round may change. That is the same shape as the verification findings elsewhere in this knowledge base (see [[techniques/verification-and-evidence]]): checkable intermediate objects plus a dedicated checker beat a single model's self-declaration.

The contract discipline also has a cost implication the paper demonstrates rather than asserts. Because the Engineer reads each dataset card at most once and the Critic receives a fixed-format package, the bounded loop used an order of magnitude fewer billed tokens than free-form agents that re-fetch and re-read cards during open-ended exploration — while roughly matching the faster baseline's latency. Bounded autonomy, in this instance, is cheaper autonomy.

For dataset search specifically, the search-to-train protocol is the methodological contribution most likely to outlive the system: it prices retrieval quality in downstream accuracy rather than in relevance grades alone, and its result — that acquisition quality matters most for weaker base models — is a concrete input to data-curation budgets. But the implication cuts both ways. A benchmark co-designed with the system's distinguishing capability, silver labels produced from the system's own evidence representation, and a three-query utility study mean the effect sizes should be treated as upper bounds pending independent replication; the durable findings are the directional ones (verification load-bearing, expansion conditional, utility measurable), not the point estimates.

## Reproducible experiment

The paper's artifacts make two reproductions possible; neither has been run by this knowledge base's maintainers, and both are described here from the paper and the repository README, not from execution.

*Retrieval reproduction.* Clone the public repository (github.com/nju-websoft/AgenticDS, Apache-2.0), which ships the implementation and the HuDS-Bench files (`HuDS-Bench/queries.json`, `HuDS-Bench/qrels.jsonl`). Rebuilding the index over the March 2026 HuggingKG snapshot and running the main configuration (GLM-5.2 backbone, Qwen3-Embedding-0.6B, T = 3) should reproduce NDCG@10 ≈ 0.6148 against the shipped qrels, and the ablation grid — Critic removed (−0.149), graph expansion without the Critic (−0.025 to −0.029) — provides a sharper falsification target than the headline number: if expansion helps without verification in a reproduction, the paper's central mechanism claim fails.

*Utility reproduction.* Take the three domain queries printed in the paper's Appendix F.2; for each compared method, fine-tune Qwen2.5-7B, Llama-3.1-8B, and Olmo-3-7B-Instruct on the method's top-5 datasets capped at 2,000 samples each (batch size 4, 3 epochs, learning rate selected from {1e-5, 5e-6, 1e-6} on a held-out development split), and score the fixed suite (GSM8K, MATH, AMC23, OCWCourses; HumanEval, BigCodeBench; MedQA, MMLU-Medical). The prediction to test is the ordering — AgenticDS first in all three domains, grand mean ≈ 52.81 versus ≈ 49.75 for the hybrid — and, more robustly, the monotone pattern that its advantage grows as the base model weakens. Independent training seeds, which the original study lacks, are the highest-value addition a reproduction could make.
