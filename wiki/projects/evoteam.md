# EvoTeam: Multi-Agent Collaboration via Evolving Teams

## What it is

EvoTeam (Cao, He, and colleagues, Jilin University and collaborators; arXiv:2610.39813, submitted 2026-10-29) is a collaboration-centric evolution framework for LLM-based multi-agent systems. Most experience-accumulation methods evolve individual agents — their prompts, skills, or memories. EvoTeam instead evolves three levels of persistent knowledge jointly, from execution experience, with the underlying LLM parameters held fixed: (1) team organization, (2) team-specific interaction rules, and (3) individual agent skills. It is an experience-accumulation framework, not a trained model and not a fixed multi-agent architecture.

The central object is a **library of reusable teams**. Each team in the library pairs a natural-language description of the collaboration requirements it supports with a candidate roster drawn from a global agent pool. For each incoming task, the system selects a team from the library whose description covers the task's collaboration requirements, or constructs a provisional new team if none matches, and then recruits a task-specific execution team from that team's roster. After execution, reflection passes update the roster and team description, the team's interaction rules, and individual agents' skills; a provisional team is admitted to the library only if its roster supports the required division of work and its collaboration structure looks reusable. After a designated evolution split, all persistent state — agent pool, team library, rule sets — is frozen, and holdout evaluation runs against the frozen system.

The paper's central design claim is an asymmetry in what gets scoped where. **Interaction rules are team-scoped**: each team owns a rule set governing handoffs — what task information and evidence a message must convey — and rules evolve only inside their team. **Individual agent skills are global**: they stay attached to agents and are shared across all teams, as are recruitment profiles. In the authors' words, "The isolation applies to team-specific rules; individual skills and recruitment profiles remain shared across team contexts."

The motivation comes from a preliminary study: naively carrying evolved collaboration experience across heterogeneous tasks can hurt. When Meta-Team (the strongest baseline, and the lineage EvoTeam builds on) was continued across tasks — starting from another benchmark with an unsuitable team template, or from another category of the same benchmark — it underperformed target-only Meta-Team on all three metrics examined. The authors diagnose two failure modes: a constrained team reorganization (a source-task team template cannot support the target task's division of labor) and inappropriate reuse of interaction rules (an inherited handoff or stopping rule misfires in a new context — the paper's example is a diagnosis-oriented rule that finalizes before coding and testing on an implementation task). EvoTeam's team library plus team-scoped rules are designed to get cross-task reuse without those two failure modes: reuse the *organization* broadly, but keep coordination guidance quarantined to the team it was learned in. Readers should note that the preliminary study's numbers appear only in a figure; no numeric values are stated in the text, so the magnitude of the motivating effect cannot be checked from the text alone.

## Mechanism

EvoTeam runs three stages per task.

**Stage (i) — Adaptive agent team composition.** The system maintains a global agent pool and the team library. An LLM-based Team Selector checks whether some existing team's description covers the query's collaboration requirements and whether its roster contains the required functional roles. Matching is on collaboration requirements — division of work, complementary roles, verification needs — not on topic similarity or benchmark identity, so tasks from different benchmarks can share a team. If no team matches, an LLM-based Composer constructs a provisional team from the pool; it serves the current task, and admission to the library is decided only after execution. An LLM-based Chairman then recruits the task-specific execution team from the selected team's candidate roster, matching the query's functional requirements to agents' specialized roles, so different tasks reusing one team can activate different member subsets.

**Stage (ii) — Team-scoped collaboration.** The Chairman decomposes the query into subtasks and an assignment plan mapping subtasks to recruited agents, based on subtask requirements and agent profiles (expertise and reliability summaries). The plan assigns responsibilities but does not predetermine interaction partners or rules. During execution, the selected team's interaction rules are injected into recruited agents' contexts as soft coordination guidance: for each handoff, the sending agent assesses a rule's applicability from the sender–recipient pair, the rule's trigger, and the current information-transfer need. A rule specifies what task information and evidence the message must convey, including uncertainty, verification, and fallback guidance; if no rule applies, the agent communicates directly. Agents execute subtasks using their accumulated skill sets. The Chairman monitors progress and can reassign subtasks within the execution team when allocation blocks progress. Execution produces a composite trace: per-agent traces (reasoning steps, tool outputs, intermediate artifacts) plus an inter-agent handoff trace (interaction events, transferred payloads, rules used).

**Stage (iii) — Multi-level experience evolution.** Three LLM reflectors update persistent knowledge after each evolution task. The Team Reflector assesses whether the team's candidate roster supports the required division of work; if not, it revises the roster and updates the team description to match — and for a provisional team, the same pass decides admission to the library. Revised teams keep their identity. The Rule Reflector examines interaction events, payloads, and rule use to find missing information or mismatches between handoff guidance and responsibilities; it creates new rules, revises existing ones, or removes rules that no longer fit — only within the selected team's rule set. The Agent Reflector inspects an agent's reasoning, tool outputs, and artifacts for useful procedures or procedural errors, and may add a procedure to the agent's skill set or revise a skill (in the implementation, agent-level guidance takes the form of short behavioral prompt patches plus reusable skills with activation conditions and verification steps), or leave the set unchanged.

## Evidence

All results below are **author-reported**; no independent replication exists. Unless stated otherwise, every method — EvoTeam and all baselines — uses GPT-5.6-Luna for task execution and, where applicable, reflection and optimization (temperature 0.2, max output 32,768 tokens), and scores are avg@3: the mean of three independent rollout scores per test instance. Evolution runs sequentially over small designated splits — 20 instances per benchmark or track, 16 for LOCA-Bench, 116 total in the mixed stream — after which the system is frozen for holdout evaluation. Benchmarks: GAIA (validation subset; 20 evolution / 100 holdout; official-evaluator accuracy), LoCoBench Python feature implementation and cross-file refactoring (20/80 each; LoCoBench Score rescaled to 0–100), LOCA-Bench (8 of 15 task types; 16 evolution cases, 240 holdout cases disjoint in both seeds and environment-description lengths; final-state success rate), and BeyondSWE CrossRepo and DepMigrate tracks (20/180 and 20/158; resolution rate counting only submissions passing all Fail-to-Pass tests with no Pass-to-Pass regressions). Baselines are a single ReAct agent (SA), a non-evolutionary multi-agent team with the same collaboration structure as EvoTeam (MAS), OWL, AgentSquare, and the experience-driven methods ReCreate, Skill-MAS, and Meta-Team, run from official implementations under shared backbone, tool access, budgets, and splits.

**Individual-benchmark evolution — the honest headline is a near-tie.** When each benchmark evolves separately, EvoTeam achieves the highest average score, 58.85, and leads on four of six metrics. But the average margin over Meta-Team is only **+0.55 points** (58.85 vs 58.30), and the wins are uneven: the margin reaches five points on GAIA (78.00 vs 73.00), while EvoTeam **loses LOCA-Bench to Meta-Team by 5.83 points** (63.75 vs 69.58) and narrowly loses BeyondSWE CrossRepo (41.11 vs 41.67). EvoTeam does outperform the unevolved MAS baseline on every metric in this setting.

**Mixed-benchmark evolution — the clean win.** When one shared system evolves over a shuffled stream of all 116 evolution instances and is then frozen and evaluated on all 838 holdout instances, EvoTeam ranks first on all six metrics and averages **59.58 vs Meta-Team's 55.55 — a 4.03-point margin**. EvoTeam's own average improves slightly relative to its individual-benchmark result (59.58 vs 58.85) while Meta-Team's declines (55.55 vs 58.30) — the pattern the framework is designed to produce, since this is the setting where cross-task reuse either helps or hurts. Skill-MAS collapses in the mixed setting (average 41.30; GAIA 36.00, below even the single-agent score from the individual setting), while ReCreate averages 49.42.

**Secondary results.** On GAIA by difficulty level (mixed-benchmark), EvoTeam posts the highest pass rates at all three levels (L1 81.58, L2 83.67, L3 38.46), with gains over Meta-Team of 2.63, 16.32, and 7.69 points — though Level 3 remains weak for every method. On LoCoBench's component dimensions, EvoTeam leads on software-engineering excellence and functional correctness for both subsets, but not on every dimension: ReCreate leads code quality on both subsets, Meta-Team leads long-context utilization on feature implementation, and the feature-implementation functional-correctness margin over Meta-Team is 0.7239 vs 0.7231 — effectively a tie.

**Cross-backbone transfer.** With evolution and evaluation backbones drawn from DeepSeek-V4.1-Flash and GPT-5.6-Luna on GAIA and the two LoCoBench tasks, EvoTeam outperforms the comparison baseline in all six configurations, with cross-backbone performance within 4.00 points of the corresponding same-backbone performance. The comparison baseline here is the **unevolved MAS**, not an evolved competitor — so this shows evolved artifacts transfer across backbones better than no evolution, not that they transfer better than a rival method's artifacts.

**Ablations.** Under mixed-benchmark evolution, the full system outperforms the variant that retains team templates but removes learned interaction rules on all four tasks examined in the main text, with the largest rule contributions on GAIA (+10.00) and LOCA (+8.75); with rules absent from both variants, retaining templates improves performance on every task (largest: GAIA +6.00, LOCA +2.50). The appendix's full six-setting version is less clean: the complete framework performs best in only **five of six** settings — removing rules slightly *improves* LoCoBench refactoring (66.40 vs 65.65), and on BeyondSWE DepMigrate removing both components beats removing rules alone (37.97 vs 36.71).

**Cost.** The authors report, in figures only, that under mixed-benchmark evolution EvoTeam achieves the highest score while costing less per task than Meta-Team and ReCreate on GAIA and BeyondSWE DepMigrate, and the highest score at the lowest estimated cost on GAIA and both LoCoBench tasks under individual evolution. No numeric per-task cost values appear in the text; per-case budgets were capped ($2.40 per task; $12.00 for LOCA-Bench).

## Limitations

**Author-acknowledged:**

- The evaluation does not systematically examine collaborative evolution in multimodal interactive environments; agents interpreting visual observations and coordinating as an environment changes are untested, and how multimodal traces would guide refinement of teams, rules, and skills is future work.
- EvoTeam accumulates experience through explicit updates while keeping LLM parameters fixed, so effective use of the experience depends on the base model's ability to correctly interpret and apply the stored guidance; combining experience reuse with model adaptation is left as future work.
- The full framework is best in only five of six ablation settings, with the two exceptions noted above (LoCoBench refactoring and BeyondSWE DepMigrate).
- The paper's LOCA-Bench case study carries the authors' own causality caveat: because the reflection process followed evaluation, the rule change it produced "does not establish the cause of the task-score difference."
- The hardest tasks remain weak in absolute terms: GAIA Level 3 pass rates are 38.46 for EvoTeam and at most 30.77 for the other evolved methods.
- The ethics section notes that persistent experience accumulation can retain sensitive information in execution traces and reusable knowledge, and that accumulated rules and skills should be reviewed for suitability before reuse in new contexts, with access controls, privacy protection, and human oversight in consequential applications.

**Analyst-assessed** (not stated by the authors):

- **No variability or significance reporting, against sub-point margins.** Results are avg@3 means; the text reports no confidence intervals, standard deviations, or significance tests. Several decisive margins are within plausible run-to-run noise: the individual-benchmark average margin over Meta-Team is 0.55 points, the mixed-benchmark CrossRepo margin is 1.11 points, and one LoCoBench dimension margin is 0.0008.
- **Transfer was never tested against an evolved competitor.** The cross-backbone study compares only against the unevolved MAS baseline, across just two backbones and three tasks. Whether EvoTeam's evolved library transfers better than Meta-Team's evolved state is unknown.
- **Cost claims are figure-only.** No per-task dollar or token figures appear in the text, so the lowest-cost claims cannot be numerically verified from the paper; the budget caps bound spend but do not report it.
- **Very small evolution splits.** The library evolves from 16–20 instances per benchmark (a single fixed shuffle order in the mixed stream). Sensitivity to which instances were chosen, or to stream order, is not reported.
- **Lineage-inherited evaluation design.** EvoTeam uses the same subsets and evolution/holdout splits as Meta-Team, and the unevolved MAS baseline uses EvoTeam's own collaboration structure. Scoring itself uses the benchmarks' native evaluators, so this is benchmark-design inheritance rather than self-grading — but split and scaffold choices were not independently chosen.
- **One model judges everything.** GPT-5.6-Luna performs task execution and all internal judgments — team selection, composition, chairmanship, and all three reflectors — for every method. There is no human or independent assessment of evolved rule or team quality.
- **Recent, thinly-tracked benchmarks.** Two of the four benchmarks are themselves very recent preprints, and the GAIA/LoCoBench subsets follow Meta-Team's selections, so external track record for these exact subsets is limited. LOCA-Bench holdout varies seeds and description lengths but only for the same eight task types used in evolution.

## Competing approaches

The paper positions EvoTeam against experience-driven and structure-search methods for multi-agent systems, and runs seven baselines under matched conditions. **Meta-Team** is the strongest competitor and the closest relative: it also self-evolves agent behavior, coordination, and team organization from collective execution experience, but without EvoTeam's team library and team-scoped rule isolation — and the head-to-head is genuinely split, with Meta-Team winning LOCA-Bench under individual evolution while losing the mixed-benchmark comparison on all six metrics. **Skill-MAS** evolves a meta-skill guiding decomposition, agent construction, and orchestration; it is competitive under individual evolution (49.17 average) but collapses in the mixed setting. **ReCreate** performs experience-driven scaffold optimization with an agent-as-optimizer; it trails on average in both settings but leads code quality on both LoCoBench subsets. **AgentSquare** searches a modular agent design space by performance rather than accumulating experience, and **OWL** is a fixed Planner–Coordinator–Worker hierarchy. The two non-evolutionary references — single-agent ReAct and the fixed MAS team sharing EvoTeam's collaboration structure — isolate what evolution adds over structure alone. The related-work landscape the paper names is broader: individual-agent evolution (Reflexion, ExpeL, Voyager, ACE, and others) and collaborative structure optimization (GPTSwarm, AFlow, EvoFlow, MaAS, MetaGPT-style fixed organizations), against which EvoTeam's distinguishing claim is collaboration-centric, team-indexed evolution — reusable teams and per-team rules — rather than prompt, topology, or single-agent skill evolution.

## Implications

If the mixed-benchmark result holds up, it identifies *where* cross-task experience should live in a multi-agent system. The preliminary study and the mixed comparison point the same way: coordination knowledge is the part that transfers badly when it is global, and the part that pays when it is indexed to a reusable organizational unit. EvoTeam's split — evolve a library of team templates broadly, quarantine handoff rules inside the team that learned them, and let individual skills float globally — is a concrete, testable answer to the negative-transfer problem that experience-accumulation systems keep hitting, and Skill-MAS's mixed-setting collapse in the same tables is evidence the problem is real and not unique to one baseline.

The result also reframes what an "agent team" is in these systems: not a per-task construction, but a persistent, revisable asset with an admission decision, an identity that survives roster revision, and its own local coordination policy. That has practical consequences for anyone operating agent fleets: team libraries become state worth versioning, auditing, and — per the paper's own ethics note — reviewing before reuse, because rules learned in one context persist and will be applied in others.

The weaker individual-benchmark result matters for interpretation. Read narrowly, EvoTeam's advantage is not "evolves better" in general; it is specifically "degrades least — and gains most — when one system must serve heterogeneous task streams." Deployments that evolve per-domain specialists may see little benefit over Meta-Team-style global evolution, and on LOCA-Bench-style long-context environment tasks they may see a deficit. The cross-backbone numbers hint that evolved organizational artifacts are partly model-portable, but until transfer is tested against an evolved competitor, that remains a plausibility result rather than a demonstrated edge.

## Reproducible experiment

The paper's code is public at github.com/DEEP-JLU/EvoTeam. For this page, the repository's README was fetched and read — **the code was not cloned, installed, or run**, and no result here is a reproduction. Per the README, the repository (Python ≥3.10; Docker required for BeyondSWE; an OpenAI-compatible LLM endpoint configured via `.env`) provides evolution and evaluation commands for both individual-benchmark and mixed-benchmark settings, including freeze scripts and an avg@3 aggregation script, and its split table matches the paper's exactly. Benchmark datasets are not bundled; they must be prepared from the official GAIA, LoCoBench, LOCA-Bench, and BeyondSWE releases.

The sharpest independent check of the paper's central claim would rerun the mixed-benchmark protocol: evolve one system over the 116-instance shuffled stream (the mixed manifests are stated to be in the repository, with the evolution manifest named `mixed_benchmark_official_116_seed20260828.json`), freeze, and evaluate on the 838 holdout instances with source-native metrics, comparing against Meta-Team evolved under the identical stream — then repeat with a different shuffle seed and a different evolution-split sample. That second repetition is the experiment the paper does not report, and it is the one that would show whether the 4.03-point mixed margin survives the two largest unquantified variance sources: stream order and split choice. A cheaper partial check is the ablation pair on GAIA and LOCA-Bench — templates without rules vs the full system — where the paper reports its largest, most checkable rule contributions (+10.00 and +8.75). Anyone budgeting a rerun should note the per-case caps from the paper ($2.40 per task, $12.00 for LOCA-Bench) and the 3-rollout avg@3 protocol, and should report rollout variance, which the paper omits.

## Evidence status

Every quantitative result on this page is **author-reported** from the EvoTeam paper (arXiv:2610.39813 v1 as read; arXiv lists a v2 revised 2026-10-30, against which these numbers have not been re-checked). The authors ran all methods themselves, using official implementations of the baselines under a shared backbone (GPT-5.6-Luna), shared budgets, and the same evolution/holdout splits as Meta-Team. Scoring uses the benchmarks' native evaluators — GAIA's official evaluator, LOCA-Bench's execution-based environment-state checks, BeyondSWE's Fail-to-Pass/Pass-to-Pass test suites, and LoCoBench's composite score — not the authors' own LLM judging final answers. No independent replication is mentioned in the paper and none is known; the paper was submitted days before this page was written. The public code repository was inspected at README level only; nothing was executed, and the evolved artifacts (team libraries, rule sets) are not distributed as downloads — they are produced by running the evolution commands.
