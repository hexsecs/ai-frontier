# Strategist: Evolving Reasoning with Agents

## What it is

Strategist is a meta-agent that evolves inference strategies across tasks. It is reported in the paper "Strategist: Evolving Reasoning with Agents" (arXiv:2611.03618, submitted 2 November 2026, cs.AI and cs.CL), with the arXiv comments field recording "NeurIPS 2026"; the abstract page carries no journal reference, so the inspected text states a venue but does not contain peer-review confirmation. The paper lists four authors: Taiming Lu and Zhuang Liu (Princeton University) and Qi Xu and Zhigang Hua (Meta). The code is linked as github.com/zlab-princeton/Strategist.

The premise the paper argues is that a model is only half of an AI agent system: the other half is the inference strategy, the reasoning procedure that turns model calls into a response, and that half is today written by hand, one system at a time, with the experience of building one strategy never carrying to the next. The paper's differentiation is against a specific family of prior work: methods that search over strategy designs (as raw code or assemblies of fixed components), train routers that select among existing strategies, or optimise one strategy per task all beat hand-designed strategies on individual benchmarks and all stop there. Searching or routing over a fixed set of strategies cannot discover a new one; trained optimizers must start over for every task. Strategist's claim is to make strategy design *cumulative*: every candidate enters a shared library, so later tasks build on earlier discoveries.

The headline author-reported results: on 30 benchmarks Strategist beats the strongest baseline on 24, matching its average accuracy (74.7 % vs 74.0 %) at 39 % lower inference cost; the strategies transfer to unseen tasks and to other models without further search.

## Mechanism

**The Strategy Blueprint.** A blueprint is a Python program that captures the structure of a reasoning strategy without the task-specific prompts — for example, a loop that generates three candidate answers, reviews each, then majority-votes. Filling in the prompts yields a runnable strategy. Every blueprint exposes one interface, `execute(llm, task) -> str`, and is built from two foundations: *chat* (a single- or multi-turn conversation) and *agent* (with scaffold and tools). Because the interface is shared, any blueprint can be used as a component inside another, so the library compounds: early blueprints build on the two foundations, later ones compose from those, and composition depth grows naturally.

**Multi-tier model routing.** Strategies may route across three model tiers (fast, balanced, complex), each in two modes (nothink and thinking), mirroring the tiered pricing and effort levels of common providers. Each reasoning step can target a different tier; the paper presents this internal routing as what allows one strategy to be accurate and cost-efficient at the same time.

**Library protocols.** Four rules govern the library graph: a shared interface; no forward calls (a node may only call nodes created before it); no cycles; and no duplicates. Blueprints are stored with traits, a *measurement card* and *experience notes* written by previous strategists.

**The four-stage loop.** Given a task and a small development set, Strategist runs N iterations, each proposing K = 5 candidates.

1. **Retrieve.** The strategist issues two textual queries: a relevance query summarising what the task asks for, and an *inspiration* query phrased to deliberately drift from the task description (for example asking for "multi-path verification on long-context QA" when the task is short-form math). Each query is scored by a hybrid function s = α·s_tfidf + (1 − α)·s_emb with α = 0.4 over every blueprint's index entry; s_tfidf is computed over the blueprint name, one-line description, when-to-use field and trait tags, and s_emb is the cosine similarity between the query and an all-MiniLM-L6-v2 embedding of the blueprint's measurement card and experience notes. Each query returns its top-5 blueprints, with the inspiration slate deduplicated against the relevance slate, so the strategist sees 10 blueprints per iteration: 5 relevance hits with their cards rendered in full and 5 adjacent inspirations with only the one-line description.
2. **Propose.** Each candidate blueprint is one of three kinds — *new* (no library backbone), *composed* (wraps or extends an existing one) or *reuse* (directly applies an existing blueprint with new prompts) — paired with task-specific prompts to form a candidate strategy. Every iteration must include at least one candidate of each kind and of each target (accuracy, efficiency, balanced); slates that violate this, that deduplicate a recent candidate, or that omit required JSON fields are rejected and the strategist is re-prompted. The strategist returns Python code followed by a JSON block with six required fields per candidate (name, kind, target, tier_mode_anchors, why, builds_on) and an optional prompts field, plus three search-side fields (search_queries, read_cards, experience). A non-fatal AST audit checks that `builds_on` matches the imports in the code block; warnings are fed into the next iteration's prompt rather than killing the run.
3. **Evaluate.** Two levels operate. At the *agent level* (inner loop) each candidate strategy processes inputs directly and the strategist observes the full reasoning trace, execution status and scores. At the *meta level* (outer loop) the strategist uses those observations to improve its proposals. The data is split four ways: the *training set*, whose full traces the strategist sees; the *validation set*, where only aggregated scores are visible; the *hidden set*, used to select the winning strategy across all iterations and never shown to the strategist; and the *test set*, held out of the search loop entirely and used only for the final number.
4. **Accumulate.** The library stores blueprints, not strategies: the reusable structure is retained and the task-specific prompts discarded, which is what enables cross-task transfer. Each iteration the strategist writes an analysis of each candidate's structural properties and adds the underlying blueprints to the library with measurement cards and experience notes. Duplicate detection is structural: two blueprints are duplicates if their `execute` function bodies hash to the same value after task-specific string literals (prompts, format instructions) are elided, computed over the Python AST so whitespace and comment changes do not produce spurious distinctions; duplicate proposals are rejected at submission time and never enter the library. The *experience* field is the strategist's own writeback: every blueprint it referenced must come back with one numerical observation and one concrete recommendation.

**Selection.** After N iterations, the candidate that beats the reference baseline on both the validation and hidden splits by the largest hidden-set margin is returned, or the baseline itself if none does.

**Search budget.** The search runs for N = 10 iterations per benchmark at K = 5 candidates, each evaluated on all three development splits — about 60 candidates per benchmark, roughly 20,000 candidate-sample executions for a benchmark with 100 rows per split, plus about 135k prompt tokens and 45k response tokens for the strategist (about 10k prompt tokens per iteration). The paper notes this dominates the per-task cost and amortises across future tasks via library reuse.

**Infrastructure.** Task models are Qwen3-0.6B (fast), Qwen3-1.7B (balanced) and Qwen3-4B (complex), each in nothink and thinking modes — six configurations. The strategist itself is GPT-6 (gpt-6-sol), accessed through the Codex CLI; it writes strategies but never answers questions. Executors are served via vLLM on 8 × NVIDIA H200 GPUs (144 GB each); agent-tier strategies execute through OpenHands with TerminalTool and FileEditorTool only and no internet access, with subprocess concurrency capped at 48 to avoid timeouts. Each LLM call from a strategy uses max_tokens = 16384.

## Evidence

All results in this section are **author-reported** from this single preprint; none has been independently replicated.

**Setup.** 40 benchmarks across seven categories (math, commonsense, knowledge, multi-hop QA, logic, code, recommendation). 30 randomly selected benchmarks form the main results and 10 are held out for one-shot retrieval. Each benchmark is split into training, validation and hidden sets of up to 100 samples each, plus a fixed 200-sample test set; the development rows come from a separate pool of 300 rows where available, and AIME 2024 and Amazon-Rec, whose questions are about 10× longer to solve, use 50 rows per split. Splits are deterministic.

**Baselines and comparison point.** 18 baselines are each evaluated at all six tier/mode configurations, giving 108 cells per benchmark. The comparison point, BL, is the cell most accurate on the benchmark's *training* split, scored on the test set. The baselines are direct, chain-of-thought, self-consistency, direct-thinking, tree-of-thoughts, least-to-most, chain-of-verification, self-discover, self-refine, monte-carlo-vote, shortlist-vote, vanilla-agent, agent-code, multi-agent-debate, MetaGPT, AutoGen, chain-of-agents and reflexion.

**Metric.** Accuracy, and *weighted cost*: token usage (input and output) weighted by tier — fast = 1×, balanced = 2.83×, complex = 6.67× — matching the 0.6B/1.7B/4B parameter ratio, on the argument that per-token forward FLOPs scale as ≈2N for a dense decoder-only transformer. Input tokens count at the same per-token weight; tool execution for agent strategies is not charged; thinking-mode tokens count as output tokens.

**Main results (Section 5).** Strategist wins on 24 of 30 benchmarks, ties on 2 (MBPP+, MinervaM), trades accuracy for cost on 2 (MedQA, AIME) and loses on 2 (HotpotQA and COPA, at equal accuracy but 9 % and 6 % higher cost). It cuts weighted cost by more than 2 % on 26 of 30. On average it matches BL's accuracy (74.0 % → 74.7 %) while reducing weighted cost by 39 %, a mean per-benchmark cost ratio of 0.61×. A win requires being better than BL on accuracy by more than 2 points or on cost by more than 2 %, and worse on neither.

The largest accuracy gains come with large cost cuts: SQuAD v2 (73.2 % → 79.1 % at 0.23× cost), TruthfulQA (+4.5 points), 2WikiMQA (+4.0 at 0.34×), Amazon-Rec (+4.0), SAT-Math (+3.6 at 0.41×), LSAT-AR (+3.4) and LSAT-RC (+3.0 at 0.50×). On benchmarks where the models are near their accuracy ceiling (MMLU, GSM8K, ASDiv, SciQ, MMLU-STEM-Hard), Strategist keeps accuracy within 2 points of BL and cuts cost instead, by 66–89 %. It is not Pareto-improving everywhere: on MedQA and AIME 2024 it is cheaper (0.44× and 0.77×) but 4–5 points less accurate. The paper also notes that of the 24 wins, some come from simpler baseline scripts found during search that match BL's accuracy at lower cost.

**One-shot library retrieval (Table 3).** The 30 main searches grew the library to 1,865 blueprints. On the 10 held-out benchmarks, the strategist queries the final strategies of the main searches once, instantiates the top-5 retrieved blueprints, measures each on up to 300 development questions and runs the chosen one on the test set, with no search. It stays within 2 points of BL's accuracy on all 10 and above it on 8 (77.8 % → 81.4 % on average) and wins on 6. The paper states that on BoolQ, SIQA and DROP it is more accurate but costlier than their very cheap BL (1.0–4.9k per sample), and that on QUALITY it costs 7 % more at equal accuracy. Its own Table 3 is not fully consistent with that sentence: it shows DROP's cost falling by 92.4 %, and a later sentence in the same section names only BoolQ and SIQA as the costlier cases, putting their ratios at 32× and 4.5×. Its per-benchmark average cost is 0.77× BL's when BoolQ and SIQA are excluded.

**Anatomy of a discovered strategy (Section 6).** One strategy designed for Amazon-Rec builds a user profile with cheap calls, extracts brand and category signals, conditionally routes to a multi-agent debate only for users with shifting preferences, then merges and audits the top picks. The branching is cheap deterministic logic deciding which inputs deserve the expensive call, and the conditional routing, merge weighting and audit step all emerged from iterative proposals against measured accuracy.

## Limitations

**Stated by the authors.** The paper's own framing constrains the claims: searching or routing over a fixed set of strategies cannot discover a new one, and trained optimizers must start over for every task. Within the paper, the search is bounded by design — the strategist sees training traces and validation scores at every iteration, so the training–hidden gap (1.2 to 2.5 points) is the paper's own guard against fitting noise; selection on the hidden split contributes 4.3 points of apparent advantage against 0.7 points on the unbiased test split, a gap the paper reports rather than hides. Baselines do not internally route across tiers within a single run, and the paper states that mixing tiers within one strategy is part of the design space Strategist searches over, which makes the BL comparison a single-configuration cell against a routed strategy. The zero-shot ablation reports three crashed runs, counted as zero.

**Assessed from the reporting.**

- **Single source.** Everything rests on one arXiv preprint (v1, 2 November 2026) by four authors at two institutions, with a venue comment ("NeurIPS 2026") but no peer-review confirmation in the inspected text. No independent replication is known.
- **The headline "beats the strongest baseline on 24 of 30" is a win against a single cell.** BL is one cell of 108 — the most accurate on the training split — and a win needs only 2 points of accuracy or 2 % of cost. The average accuracy difference is 0.7 points, i.e. within the paper's own tie threshold. The honest summary is "matches the strongest baseline at 39 % lower cost", which the abstract also states; the 24/30 win count is the more quotable number and the less informative one.
- **The comparison is between a routed system and unrouted baselines.** Each baseline is evaluated at one tier/mode per run, while Strategist may route across tiers within a run. The paper presents this as part of the searched design space, but it means part of the 39 % cost saving is available in principle to a hand-written tier-routing baseline that the 18-baseline matrix does not contain.
- **Cost is a self-defined unit.** Weighted tokens are proportional to parameter count, tool execution is not charged, and thinking tokens are counted as output tokens. A strategy that spends more thinking tokens to save tier upgrades is charged differently than one that does the reverse. The cross-model transfer experiments switch to USD at list prices, which is a different accounting from the main tables and is not reconciled with them.
- **The cost claim is dominated by a handful of cheap baselines.** On one-shot retrieval the per-benchmark average cost ratio is 0.77× BL only after excluding BoolQ and SIQA, whose single-call baselines make the ratios 32× and 4.5×; the paper's Table 3 also shows two large cost increases, BoolQ (rendered as ↑3103 % in the source) and SIQA (↑337 %). The paper is candid about these, but the averages hide them, and its prose on which benchmarks are costlier is internally inconsistent (see Evidence).
- **The library's contribution is asserted by an ablation that removes two things at once.** "Iteration without the library" disables both retrieval of relevant blueprints and the adjacent-inspiration mechanism, so the 13.3-point drop cannot be attributed to the library's compositional reuse rather than to the loss of cross-task inspiration. The one-shot retrieval experiment (library, no search) is the cleaner measurement, and it is on 10 benchmarks.
- **Transfer results are partly credit-assigned to broken baselines.** The paper states that part of the GPT-5 margin comes from `self_refine` and `multi_agent_debate` returning malformed answers on the new backend — so some of the 7-of-10 win count is the baseline failing, not the strategy winning. On Gemini, SQuAD2 is cheaper but less accurate and MinervaM loses 9.4 %.
- **The library grows by accumulation, so quality is not audited.** 1,865 blueprints entered the library from 30 searches; measurement cards are written after a blueprint has been evaluated at least once, and experience notes are the strategist's own self-reports. Nothing in the inspected text measures the fraction of library entries that are actively useful, nor the effect of a bad card on later searches. This is the [[concepts/evaluator-circularity]] risk in a self-referential form: the notes that guide future searches are written by the same model that produced the blueprint.
- **No significance testing.** The reported quantities are means over 100-row development splits and a fixed 200-row test set, with no confidence intervals or paired tests for the 74.0 % → 74.7 % difference or for the per-benchmark win/loss counts.
- **The comparison frameworks are given the same meta-LLM, but their published configurations may not be.** The paper states they share the same meta-LLM and executor, which is a fairer test than quoting their papers, but the comparison is over 10 benchmarks on test accuracy only — no cost column for AFlow, ADAS, EvoFlow, StrategyLLM or AgentSquare.

## Competing approaches

**The 18 in-house baselines.** Direct (a single call with no intermediate reasoning) is the minimum-cost floor; chain-of-thought and direct-thinking isolate prompting from the model's hidden reasoning trace; self-consistency samples 33 CoT trajectories at temperature 0.7 and majority-votes; tree-of-thoughts maintains a tree of partial reasoning states scored by the model itself; least-to-most decomposes then solves sub-problems in order; chain-of-verification generates verification questions and revises on disagreement; self-discover composes a reasoning structure from a fixed pool; self-refine is a capped three-round critique-and-rewrite loop; monte-carlo-vote samples 55 traces and returns the strict majority, shortlist-vote pre-filters to a top-10 shortlist before a 33-way vote; reflexion writes a verbal self-reflection on failure and retries with it appended. The agentic baselines are a vanilla OpenHands ReAct loop with TerminalTool and FileEditorTool only, the same agent instructed to write and execute Python through the terminal tool, multi-agent debate with 33 agents revising over 22 rounds, MetaGPT, AutoGen and chain-of-agents.

**The five published frameworks compared in the ablation.** AFlow (Zhang et al. 2025c) and EvoFlow (Zhang et al. 2025a) compose strategies from fixed components or predefined modules; ADAS (Hu et al. 2025) writes strategies as raw code; StrategyLLM (Gao et al. 2024) generates, executes, optimises and evaluates strategies for one task; AgentSquare (Shang et al. 2025). The paper's positioning is that raw-code search yields isolated programs while component composition bounds what can be discovered, and that optimisation methods refine one strategy per task and start over on the next.

**The wider related-work map.** On the agent side: chain-of-thought and self-consistency, tree-of-thoughts deliberation, tool-use loops, verbal self-reflection, multi-agent conversation, and formal representations from state machines to declarative compilation to optimizable graphs. On the strategy layer as design bottleneck: automated design of agentic systems; routing methods that select among existing strategies without building them (Taparia et al. 2026, Yue et al. 2025, Zhang et al. 2025b) and controllers trained to route each input to a strategy (Su et al. 2025); optimisation methods that refine one strategy per task by reinforcement learning (Li et al. 2024, Zhang et al. 2026, Gao et al. 2025) or by LLM-driven evolution and refinement (Liu et al. 2025a). On cross-task transfer and experience accumulation: meta-learning, neural architecture search, prompt optimization, ExpeL and Voyager in the LLM-agent setting, and lifelong-agent learning as a formalised direction. The paper's own priority claim — "to our knowledge, the first automated strategy-design system that accumulates knowledge from one task to the next" — is an author claim.

**Within this knowledge base.** Strategist is the library-level counterpart to [[projects/skillcompiler]]: SkillCompiler compiles individual well-specified skill operations into validated programs inside one evolving skill, while Strategist searches whole inference strategies and carries them across task families. The distinction the page already recorded — improvement living in external state rather than in weights — is exactly the mechanism here, and [[concepts/improvement-lives-in-external-state]] is the right frame for the library, measurement cards and experience notes. The transfer experiments bear on [[concepts/capability-locus]]: a strategy that transfers unchanged from Qwen3 to GPT-5 and Gemini-2.5 is evidence that some of the observed capability belongs to the strategy and not to the executor, though the paper also shows the margin partly reflects baselines that break on the new backend. Compare the leakage discipline — hidden split, experience notes derived from training traces only, test set held out of the search loop — with [[projects/evoaudit]]'s concern with regressions, and with [[concepts/preservation-aware-agent-improvement]]: the paper's own negatives (HotpotQA, COPA, MedQA, AIME; BoolQ and SIQA cost ratios above 3×) are per-task losses that the aggregate average conceals.

## Implications

The following is analysis by the KB maintainers, not a claim of the authors.

The most transferable idea is representational rather than algorithmic: give the searched object a *single interface* so that every instance can be a component of every other, and store the searched object separately from the task-specific parts. The blueprint/proposal split — library stores structure, prompts are attached per task — is what makes cross-task reuse possible at all, and it is a concrete answer to the accumulation problem that [[concepts/improvement-lives-in-external-state]] names. A team that wants its prompt engineering to compound across tasks has to decide what the durable artefact is; the paper's answer is executable structure, and the cost of that answer is that the artefact must be program-shaped and therefore reviewable, testable and version-controllable.

Second, the ablation pattern is worth copying as a design discipline: build the system in two variants — with the shared library and without it — and report both. The 13.3-point gap between 78.7 % and 65.4 % is the kind of number that justifies an architectural commitment, and it is the kind of number most papers about accumulated experience do not report.

Third, the paper's split discipline is the transferable engineering discipline. Four disjoint subsets — training with full traces, validation with aggregate scores only, hidden for selection, test for reporting — plus the disclosure that the selection advantage is 4.3 points on hidden and 0.7 on test, is a model of honest reporting for any system that searches. The same structure applies to [[concepts/protocol-relative-scores]]: BL is chosen on the training split precisely so that the comparison mirrors deployment, where a method is picked on the small sample at hand and then applied to a larger unseen sample from the same distribution.

Fourth, the cost result is more actionable than the accuracy result, and the routing idea is the mechanism. A 39 % weighted-cost reduction at equal accuracy is a different kind of win from a 0.7-point accuracy change: it is the kind that shows up in a budget rather than in a leaderboard, and it is produced by the same artifact that a team would have to write by hand anyway — a Python program that decides which model to call, at what tier, on which inputs. The paper's Amazon-Rec example makes the shape clear: cheap deterministic branching decides which inputs deserve the expensive call, so capacity is spent where it changes the answer. That is a design any team can adopt without adopting the meta-agent.

Fifth, the negative findings are the practically useful part. The strategy that wins on 24 benchmarks still loses on 2 and ties on 2, and on BoolQ and SIQA it is 32× and 4.5× the cost of a single-call baseline for a few accuracy points. Any deployment of a searched strategy should therefore keep a per-task cost ceiling and a fallback to the cheapest baseline, because the paper's own data shows the aggregate average is not a safe guide to any individual task. This is the failure mode [[concepts/verified-completion-vs-apparent-success]] names in a different guise: a system can be better on average and still be the wrong choice on a particular task.

Finally, the self-referential risk of the library deserves engineering attention. Experience notes that guide future searches are written by the strategist that produced the blueprint, and measurement cards are self-reported. Over 1,865 entries that is a substantial unverified corpus influencing later behaviour. A practical mitigation — which the paper does not propose — is to require every card to carry a re-measured number from a held-out split before the blueprint is eligible for retrieval, and to expire cards that have not been re-confirmed. Without that, the library's long-run behaviour is governed by an accumulating set of model-written claims about model-written code, which is a governance problem before it is a modelling one.

## Reproducible experiment

The code is linked in the paper (github.com/zlab-princeton/Strategist), so a check need not start from nothing; but the load-bearing claims are about *cumulative* behaviour and can be tested without the full system.

1. **Isolate the library's contribution.** Take a small benchmark set (three or four tasks with cheap, deterministic scoring and a 100-row development split and a 200-row held-out split). Run the search twice under an identical budget — once with a shared blueprint library that accumulates across tasks, once with a fresh library per task — and compare final test accuracy and cost. Pass criterion: the library run should be ahead on the later tasks and roughly level on the first; if the fresh-library run matches it, the accumulation claim does not hold for your task mix. The paper's reference is a 13.3-point average gap between the two conditions on its 10-benchmark ablation set.
2. **Test the leakage discipline directly.** After a search, check whether the hidden split influenced anything the strategist saw: the experience notes, the measurement cards and the next iteration's prompt. The paper's design forbids it by construction (notes derive from training traces only). Pass criterion: no hidden-split-derived string appears in the library writeback. A single leak would invalidate the 4.3-point-versus-0.7-point selection analysis and every table that depends on it.
3. **Cost accounting audit.** Recompute one benchmark's cost under three definitions: the paper's parameter-weighted tokens, raw tokens, and USD at list prices, for both the discovered strategy and the strongest baseline. Pass criterion: the direction of the saving is the same under all three. A saving that inverts between weighted and raw tokens means the 39 % figure is an artefact of the tier weighting and should not be quoted as a budget saving.
4. **Per-task, not aggregate.** Replicate the comparison on 8–10 tasks and report the per-task wins, losses and cost ratios rather than the average. Pass criterion: reproduce at least one of the paper's documented negatives (a benchmark where the strategy ties on accuracy at 6–9 % higher cost, or one where the cost ratio exceeds 3×). A design that wins on every task at lower cost would contradict the paper's own data and would be a better result than the paper's — worth knowing.
5. **Transfer check.** Take the strategies discovered on one model family and run them unchanged on a different family, alongside the strongest baseline re-executed on the same backend. Pass criterion: directionally matching behaviour on the wins and, importantly, verify whether the margin comes from the strategy or from baselines that fail on the new backend — the paper attributes part of its GPT-5 margin to `self_refine` and `multi_agent_debate` returning malformed answers. Reporting the baseline health separately from the strategy result is the point of this experiment.

Model substitutions are unavoidable: the paper used Qwen3-0.6B/1.7B/4B as executors, GPT-6 (gpt-6-sol) as the strategist, and GPT-5 / Gemini-2.5 for transfer. Any substitution, and the resulting cost-weight ratios, should be reported with the results, since the cost metric is tied to parameter-count ratios.
