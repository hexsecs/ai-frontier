# TinyAstral

## What it is

TinyAstral is a two-stage recipe from Huawei Technologies / Huawei Noah Research Institute (11 authors; arXiv:2610.41216v1, submitted 30 October 2026; no venue stated) for carrying the gains of a large robot planner's *harness* — the tools, feedback, memory, and recovery logic around the model — into a compact agent with lower inference cost. The paper's motivating question: "Can improvements to a large teacher's harness be carried into a compact agent with lower inference compute cost?"

In stage 1, the authors freeze an open-weight teacher (Qwen3.8-Flash-Next, 180B) and improve only its harness through recursive self-improvement (RSI): frontier-LLM "master" agents read the teacher's trajectories, propose harness code edits, and each edit is accepted only if it passes a pre-registered paired statistical test. In stage 2, the final harness is frozen, the teacher's successful trajectories — reasoning included, plus synthetically injected failure-recovery branches — are collected, and small students (0.8B, 2B, and 4B, fine-tuned from Qwen3.5 checkpoints) are distilled to replace the teacher *inside the same frozen harness*. The scaffolding is not absorbed into the weights alone; the student is deployed within the harness that was evolved around its teacher.

One scope fact conditions everything below: **every quantitative result in the paper is simulation.** All six benchmarks (RoboTwin 2.0, Guava, LIBERO-PRO, SimplerEnv, VLABench, EB-Manipulation) are simulators. The physical-robot evidence is qualitative — trajectory figures from closed-loop runs of the 4B student on a real SO-ARM101 arm, with no success rates, trial counts, or failure statistics reported for any physical run. All results are author-reported by the single authoring team; no independent replication is cited.

## Mechanism

**Planner, harness, and scoring.** A planner controls the robot through the harness. Each turn the harness presents an observation (camera images, instruction, recent tool results, gripper state); the planner emits a reasoning trace followed by exactly one tool call; the harness executes it and returns a structured result. The model never outputs joint angles or coordinates unless a tool explicitly requests them. Observations are deliberately short-horizon: on RoboTwin the planner sees the head and both wrist cameras with only the two most recent turns' images retained (the Guava and LIBERO-PRO adapters keep the three most recent single-view images), alongside scene object names, a proprioceptive gripper line, the previous tool result, and a call counter. The harness owns perception (SAM 3 segmentation lifted to depth point clouds), grasp and placement geometry, collision-free motion planning, and closed-loop corrections; the planner decides object, part, reference, spatial relation, arm, order, and when to stop. Tools "report what they measured rather than what they intended": a `place` call re-measures after release and returns `OFF_TARGET` with the offset, and unmeasurable checks return `ok=null` ("unknown") rather than a pass. The agent ends an episode by calling `done` with predicates it believes hold; the harness verifies them and rejects failed checks (after two rejections, the next `done` ends the episode unchecked). The environment's success flag never enters the model's input. The primary metric is **strict success**: the agent ended the episode with `done` *and* the benchmark's success predicate holds in the final state. Undetermined outcomes count as failures in all headline numbers.

**Stage 1 — gated harness evolution.** The evolving system is the frozen teacher, the current harness, and a master: "Only H changes. The weights of π_T stay fixed throughout, and M does not act in the environment." Humans specify the rules — including the pre-registered acceptance criteria — and the budget before the loop begins. Each round, the master assigns observed failures to one of ten failure classes (off-target placement, false completion, missing primitives, task-memory errors, instance misidentification, among them), proposes edits targeted at a failure cluster (new tools or primitives, more honest tool returns, perception fixes, failure handling, memory corrections), and the candidates face the gate. Code may not branch on the task name; in the final integration phase the system prompt and existing tool descriptions must remain byte-identical to the parent, and every new component must fire through an explicit trigger that writes a marker to the log, with a code audit verifying step-for-step equivalence with the parent when the trigger does not fire.

The acceptance gate (Appendix E, pre-registered) works in two steps. A direction screen discards any candidate whose task-averaged 95% upper bound of gain on its target cluster falls below +2 pp. Survivors merge into one candidate harness, run interleaved with the parent on ~1,150 pre-registered (task, seed) pairs, with training, selection, and evaluation seeds in disjoint ranges. The candidate is accepted only if the one-sided 97.5% lower bound of the paired gain — computed by a task-clustered bootstrap — is positive, and the net number of wins on the target cluster is positive; it is vetoed if the untriggered set regresses by at least 2 pp with a two-sided 95% upper bound below zero. A futility stop fires at halfway if net gain is non-positive or conditional power falls below 10%. Over the whole run the master proposed **296 candidate capabilities: 121 adopted, 16 adopted and later superseded, 142 rejected, 17 undecided — a final harness of 101 capabilities** (87 verbatim, 14 in a successor form). The final integration phase accepted three of seven candidates. On RoboTwin only, the harness also reads one short end-state note per task (no actions or trajectories), refined during RSI on development seeds and frozen read-only at evaluation; the other five benchmarks use no task memory.

**Stage 2 — supervision and distillation.** With the final harness frozen, the teacher generates three kinds of supervision. First, its reasoning is kept: each target is the teacher's rationale plus its next tool call. Second, recovery branches: from a successful episode, the first k calls are replayed in a fresh simulator with the same seed, a perturbation is injected at the branch point (on RoboTwin, the grasped object slips or the target is moved 6–10 cm before the next grasp; on Guava/LIBERO, a grasp misses, a push falls short, or a placed object is displaced), and the teacher continues online — a branch is kept only if the perturbation took effect, the replay reproduced every recorded result code, and the teacher still reached strict success. Third, main episodes run at temperature 0 (failed training seeds retried up to twice at 0.7), and only episodes the teacher ended with `done` and the benchmark judges successful are kept; success labels are used offline for selection and never appear in training messages. Half the final training set is offline *real-robot* auxiliary data: public datasets (AgiBot World; Fractal, BridgeData V2, DROID, Berkeley UR5 via Open X-Embodiment) cast into harness-format tasks — state and failure judgment (27,918 samples), sub-goal planning (4,187), and next tool call (9,771). For next-call samples the teacher first predicts the call unseen; if it matches the dataset action its reasoning is kept, otherwise it explains the reference call STaR-style, kept only if it passes consistency and quality checks (the relabeling retained 19,598 of 23,070 candidate steps: 4,509 from matching first predictions, 15,089 explained given the reference call).

The final set has **83,753 decision samples — 41,877 simulated and 41,876 real-robot auxiliary** (recovery branches are subsampled to 20% of the RoboTwin portion). Training fine-tunes all language-model parameters of Qwen3.5-4B for 2 epochs (vision encoder and projector frozen; lr 1e-5 cosine, 5% warm-up, batch 32, max length 12,288 tokens, loss on the final assistant turn only); the 0.8B and 2B students use the same data and recipe. At deployment the student replaces the teacher inside the frozen harness, served in bf16 on one accelerator.

## Evidence

All figures are author-reported. RoboTwin evaluation is 500 episodes (50 tasks × 10 seeds, seeds ≥ 100,000, disjoint from selection and training); Guava 450, LIBERO-PRO 300, SimplerEnv 960, VLABench 500, EB-Manipulation 228. Author-run comparisons are paired on identical (task, seed) episodes.

**Harness evolution and transfer (RoboTwin, strict success).** Evolution raises the frozen teacher from **33.4% at the initial harness to 63.6% at the final harness** (snapshot lineage: 33.4, 33.6, 49.4, 50.8, 54.6, 60.4, 63.6 — gains accrue across the whole run rather than in one jump; the teacher's "ever success" at the final harness is 68.8% against the 63.6% strict figure). The gain is not teacher-specific: DeepSeek-V4.1-Flash, "which was not the planner used during harness evolution, improves by 30.6 pp without model-specific harness changes" (32.8% → 63.4%), and the *untrained* Qwen3.5-4B gains +26.6 pp from the harness alone (14.6% → 41.2%). A separate 4B student trained for each harness version tracks its teacher at every snapshot (36.2% at H_1 — slightly above the H_1 teacher's 33.4% — to 62.8% at the final harness). Within the final harness, distillation adds **+21.6 pp** over the untrained 4B initialization (62.8% vs. 41.2%).

**Final system.** TinyAstral-4B stays close to its 180B teacher on all three training benchmarks (RoboTwin 62.8% vs. 63.6%; Guava 93.6% vs. 94.7%; LIBERO-PRO 78.3% vs. 80.0%) and lands within 5.0 pp of the teacher and within 2.4 pp of the 552B DeepSeek-V4.1-Flash on the zero-shot benchmarks, all in the same harness. Distillation over the untrained init is worth +10.0 pp on SimplerEnv (Google Robot VM) and +13.6 pp on VLABench. The size story is bounded: the 0.8B student nearly matches the 4B on RoboTwin (61.8% vs. 62.8%) and Guava (93.8% vs. 93.6%) but falls to 54.7% on LIBERO-PRO against the 4B's 78.3% — "the effect of model size is therefore most pronounced on LIBERO-PRO."

**Ablations (paired, one ingredient changed).** Keeping the teacher's reasoning text in the targets has "the largest measured effect among our ablations": emptying it costs **−19.3 pp on LIBERO-PRO, −11.2 pp on SimplerEnv Google VM, and −10.0 pp on VLABench** (−4.7 pp on Guava, only −0.4 pp on RoboTwin); on LIBERO-PRO, 49 of 300 episodes end at the call limit without reasoning targets, vs. 7 under the full recipe. The real-robot auxiliary data shows a sharp split: removing it collapses held-out real-robot next-call accuracy from **0.923 to 0.235**, while producing no statistically detectable change in simulated success (per-benchmark deltas are small and mixed, sometimes slightly positive without it). Of the 271 zero-shot episodes the student solves but the untrained 4B does not, 63% end with the untrained model exhausting its call budget — consistent with the harness-plus-distillation gain being substantially a persistence/recovery effect.

**Cost.** On the same 20 SimplerEnv episodes, the 4B student uses **25.3 accelerator·seconds per episode vs. 123.8 for the teacher (4.9×)** and 249.6 for DeepSeek-V4.1-Flash (9.9×) — "about one fifth of its teacher's accelerator time." Success on those 20 episodes was 14/20 (student) vs. 12/20 (teacher).

## Limitations

The paper has **no Limitations section**; its only forward-looking statement is that "future work will extend the approach to more RSI environments." The constraints below are evident on inspection of the text and appendices, except where noted.

- **Stage 1 is the least reproducible part of the work.** The master agents are never named — they are only "a set of frontier LLM agents" — and the RSI stage's compute cost is never reported: no GPU-hours, no API cost, no round count beyond the capability ledger. The paper also reports no compute figures for teacher trajectory collection or student training. The most novel component is the least inspectable, and its cost is exactly the quantity a reader needs to weigh the recipe against simply training longer.
- **The competitor-harness headline carries a confound disclosed only in the appendix.** The striking comparisons — the student in the authors' harness at 93.6% vs. the teacher in the Guava harness at 78.9% on Guava, and 78.3% vs. 57.3% (MotorMind) and 53.0% (PyRUA-Lean) on LIBERO-PRO — ran the teacher at reduced settings in at least the Guava harness: "medium reasoning effort and default sampling," versus its "default xhigh reasoning and temperature 0" in the authors' own harness (Appendix B). Part of those gaps may be decoding configuration rather than harness quality. The authors disclose the asymmetry in the appendix but not alongside the headline claim.
- **The development benchmark is the headline benchmark.** RSI evolved the harness on RoboTwin, and RoboTwin supplies the 33.4% → 63.6% headline. The mitigations are real — evaluation seeds are disjoint from selection and training, acceptance runs on selection seeds only, and gains appear on five other benchmarks — but the harness design and the RoboTwin-only task-memory mechanism are RoboTwin-tuned, and the four-version transfer study exists only on RoboTwin.
- **Physical evidence is qualitative only.** Despite the robotics framing, every number is simulated; the real SO-ARM101 runs (two tasks named in §4.4; the Figure 2 caption says three) appear as trajectory figures with no success rates or trial counts. The one physical-world metric, next-call accuracy of 0.923, is an offline prediction score on held-out dataset episodes — and it depends entirely on the real-robot training half of the data (0.235 without it), which says nothing directly about closed-loop physical success.
- **The cost headline rests on 20 episodes.** The 4.9× figure uses median durations over 20 SimplerEnv episodes, and the success counts on those episodes (14/20 vs. 12/20) are within noise of each other.
- **Ecosystem recency.** The teacher, the 552B comparison planner, the student base models, and several compared systems are very recent, pre-release-class models; independent verification by other groups is not yet possible for several of them. Author-acknowledged comparison asymmetries also exist and are disclosed by the authors in protocol notes — e.g. PyRUA-Lean-4B is disadvantaged by the withheld per-step success signal it was trained with, and unknown outcomes are conservatively counted as failures with upper bounds reported (the untrained 4B's LIBERO-PRO score rises to at most 57.3% if all 63 undetermined episodes are counted as successes — still below the student's 78.3%).

## Competing approaches

The paper positions itself against three families. **Harness-evolution systems** (PhysEvo, HarnessPAI, ASPIRE, RoboRSI systems) improve scaffolding around a planner; TinyAstral's claimed differences are that evolution runs *continually under paired statistical selection* rather than being hand-designed or validated once before release, and that gains are measured across multiple planners at successive harness snapshots. **Concurrent self-improvement work**: SenseNova-RoboRSI trains a 27B VLM on validated interaction experience; World Action Agent distills skill-evolved harness traces into a 9B VLM. **Small-agent distillation**: Guava distills frontier-VLM reasoning and recovery trajectories into a 4B model inside a hand-designed harness; PyRUA-Lean trains a 4B coder with GRPO. End-to-end VLAs (OpenVLA, π_0, π_0.5) are the architecturally different baseline family.

The paper's own comparison numbers, kept in the paper's two evidence tiers. *Same episodes, run by the authors from released code/weights:* Guava-4B scores 84.4% on Guava in its official harness (vs. TinyAstral-4B's 93.6% in the evolved harness); PyRUA-Lean-4B scores 12.8% on RoboTwin and 17.7% final-state success on LIBERO-PRO, with the authors' caveat that it is "trained and self-evaluated with a per-step environment success signal; without this signal, which our protocol withholds, it often declares success prematurely"; SenseNova-RoboRSI-27B reaches 70.3% on LIBERO-PRO under its official stop-on-success rule (vs. 78.3%). *Published results under their own protocols and episodes (not same-episode):* GPT-6 Astra one-shot reaches 73.6% on RoboTwin and PyRUA-Lean with GPT-6 Astra 69.2%, both above TinyAstral-4B's 62.8% — under different protocols; the paper notes the student "exceeds published results from π_0-FAST on both SimplerEnv robots and π_0 on VLABench, although these baselines were fine-tuned on in-domain data."

## Implications

The transfer results are the paper's most portable finding: an evolved harness lifted two frozen planners it was never evolved around by roughly the same margin as its own teacher (+30.6 and +26.6 pp, vs. +30.2 for the teacher). If that holds beyond RoboTwin, harness quality is a separable, reusable asset — improvable once under statistical discipline and then inherited by whatever planner is deployed inside it, including a distilled 4B student at roughly a fifth of the teacher's inference cost. The reasoning-text ablation points the same way: what transfers is not just successful actions but the teacher's stated reasoning about them, and removing it is the single most damaging change measured. For the KB's purposes, TinyAstral is also a clean instance of improvement living in external state: every stage-1 gain was obtained with the teacher's weights frozen, and the statistical gate — pre-registered criteria, paired tests, a regression veto — is the mechanism that keeps that external-state improvement honest rather than anecdotal. The open questions are the ones the Limitations section names: whether the recipe's stage-1 cost (unreported, and dependent on unnamed frontier models) is repayable, and whether any of it survives contact with physical robots at measured rates.

## Reproducible experiment

A true replication is not extractable: the paper text releases no code, harness, or ledger, and stage 1 depends on unnamed frontier-LLM master agents plus unreported compute. What a reader *can* run today, using only the paper:

1. **Internal-consistency recomputation from Appendix B raw counts.** Guava-4B 380/450 = 84.4%; PyRUA-Lean-4B 64/500 = 12.8% on RoboTwin; SenseNova-RoboRSI-27B 211/300 = 70.3%; PyRUA-Lean-4B LIBERO-PRO final-state 53/300 = 17.7%. All reproduce the printed percentages exactly.
2. **Gain and bound arithmetic.** Table 1's gains are simple differences of tabulated rates (63.6 − 33.4 = 30.2, etc.), and every unknown-outcome upper bound in Table 5 can be recomputed from the printed S, U, and N (e.g. untrained 4B on LIBERO-PRO: strict 36.3% with U = 63/300 gives ≈ 57.3).
3. **Re-implement the acceptance gate.** Appendix E specifies it completely — direction screen, ~1,150 paired (task, seed) pairs, task-clustered bootstrap bounds, veto and futility rules — so the gate itself can be exercised on any paired binary-outcome data, e.g. published per-episode RoboTwin baseline results, even though the authors' own RSI run cannot be repeated.

## Evidence status

All benchmark results on this page are **author-reported** results from the single authoring team (Huawei / Noah's Ark Lab); no independent replication is cited, and several models involved are too recent for third-party verification. The paper text itself gives **no code, data, or weights URL** — the only repository URL in the text is a competitor's. The project page linked from the arXiv metadata in turn links a code repository, an SFT dataset, and weights; per house rules, those artifacts were **not inspected or executed** for this page, and nothing here claims they were. The stub's claims were re-verified against the full text in this pass: the two-stage summary and the scaffolding-transfer framing are confirmed, with two precisions the stub missed — the student is deployed *inside* the frozen harness rather than absorbing it into weights alone, and the harness also transfers sideways to other frozen planners with no distillation at all. The stub's implicit suggestion of physical-robot results is corrected in emphasis: all benchmark numbers are simulation.
